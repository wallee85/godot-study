# Godot 环境、工具与生态

> 本文是选型指南，不会替你下载或安装任何软件。按项目需要挑选即可，不必一开始把整套工具链装齐。
>
> 本仓库教程目前以 **Godot 4.7.2 stable** 为例。新建项目时优先使用官网当前 stable 版本；打开旧项目或安装插件时，先确认它们支持的 Godot 主次版本。

## 1. Godot 是什么，以及它自带什么

Godot 是一套开源、跨平台的游戏引擎。编辑器已经包含场景与节点编辑、脚本编辑、动画、UI、物理、音频、调试器和性能分析器；可以先只装 Godot，直接完成本仓库的 2D 教程。

Godot 也不是必须搭配某个第三方“游戏框架”才能开发。场景树、节点、信号、资源、输入映射、UI、动画和物理等基础设施都由引擎提供。社区框架和插件是在特定需求出现后再添加的。

## 2. 语言与运行平台怎么选

| 路线 | 适合谁 | 需要的环境 | 重要限制 |
|---|---|---|---|
| **GDScript** | 初学者、快速迭代、跟随官方教程 | Godot 标准版即可 | 与 Godot 编辑器和 API 结合最紧密；需要浏览器发布时优先选它 |
| **C#** | 已熟悉 .NET、希望使用 C# 生态或测试工具 | Godot .NET 版 + .NET SDK + C# IDE | Godot 4 的 C# 项目目前不能导出 Web；移动平台支持有额外限制，先核对官方文档 |
| **C++ / Rust 等原生扩展** | 性能热点、复用原生库或开发引擎扩展 | GDExtension 对应语言的绑定、编译工具链 | 属于进阶路线；绑定由社区维护，需自行核对引擎版本、目标平台和维护状态 |

**建议**：本仓库的入门主线用 GDScript；已有 C# 经验且不需要 Web 导出时，可按教程中的 C# 对照学习。不要为了“以后可能用到”而提前引入多语言或原生扩展。

Godot 4 的 C# 平台说明见[官方 C# 文档](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html#doc-c-sharp-platforms)，C++ 及其他语言路线见[官方脚本语言索引](https://docs.godotengine.org/en/stable/tutorials/scripting/index.html)。

## 3. 编辑器与开发工具

### 编辑器和代码编辑器

| 工具 | 推荐用途 | 备注 |
|---|---|---|
| **Godot 内置脚本编辑器** | GDScript 入门、跟随本仓库教程 | 零配置，场景、脚本、调试器在同一处；初学阶段完全够用 |
| **Visual Studio Code** | GDScript 外部编辑；也可用于 C# | 可选装社区的 [Godot Tools 扩展](https://marketplace.visualstudio.com/items?itemName=geequlim.godot-tools)；外部编辑器需要在 Godot 中配置，详见[官方说明](https://docs.godotengine.org/en/stable/tutorials/editor/external_editor.html) |
| **JetBrains Rider / Visual Studio** | C# 项目 | 适合 .NET 工作流；用 C# 时仍需安装 Godot .NET 版和 .NET SDK |

VS Code 扩展和其他 IDE 插件属于独立项目，不等同于 Godot 官方内置功能。遇到补全、调试或版本不兼容时，可先退回 Godot 内置脚本编辑器判断问题是否来自扩展。

> **扩展报 `Couldn't connect to the GDScript language server at 127.0.0.1:xxxx`？** GDScript 语言服务器由**正在运行的 Godot 编辑器**提供，不是扩展自带的，所以要同时满足两点：
> 1. Godot 里**已经打开了这个项目**（停在项目管理器不算），并且 VS Code 打开的是**项目根目录**（即含 `project.godot` 的那一层）。
> 2. 两侧端口一致：VS Code 的 `godotTools.lsp.serverPort` 对应 Godot 的「编辑器设置 → 网络 → 语言服务器 → 远程端口」。Godot 4.7 默认 **6005**，而扩展默认 **6008**，把其中一个改成另一个的值即可。
>
> 不想一直开着 Godot 编辑器，可以把 `godotTools.lsp.headless` 设为 `true` 并配好 `godotTools.editorPath.godot4`，扩展会自己拉起一个无窗口 Godot 充当语言服务器。
>
> **扩展报 `The specified Godot executable, '...' is invalid`？** `godotTools.editorPath.godot4` 要填 **Godot 可执行文件**的完整路径（Windows 上形如 `D:\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64.exe`），而不是项目目录或 Godot 安装目录。该值默认为 `godot`，扩展会先按 PATH 查找，失败后再相对**工作区根目录**解析；如果工作区里刚好有同名的 `godot` 目录（本仓库就是这种情况），就会被当成可执行文件而报此错。设置写在用户或工作区 `settings.json` 均可，改完需要用 `Developer: Reload Window` 重新加载窗口才会重新检测。

### 项目管理与日常必备

- **Git 版本控制**：建议从第一个项目开始使用。可选 Git 命令行或 GitHub Desktop；把项目源文件和 `project.godot` 纳入版本控制，遵循 Godot 生成的 `.gitignore`，不要把临时导入缓存提交上去。
- **Godot 官方示例**：[godot-demo-projects](https://github.com/godotengine/godot-demo-projects) 适合查官方 API 和最小示例；也可以在浏览器里直接[试玩](https://godotengine.github.io/godot-demo-projects/)。
- **官方文档与社区**：[稳定版文档](https://docs.godotengine.org/en/stable/)和[Godot 官方论坛](https://forum.godotengine.org/)。
- **性能诊断**：先使用编辑器内置 Debugger、Profiler、Monitors 和 Remote Scene Tree。遇到真实瓶颈再考虑 [Tracy](https://docs.godotengine.org/en/stable/engine_details/development/profiling/tracy.html) 等外部分析器，不要先凭感觉优化。

### 美术、音频与关卡工具

按项目类型选用，不是 Godot 的依赖：

| 任务 | 常见工具 | 适用场景 |
|---|---|---|
| 像素画 / 2D 绘图 | [Aseprite](https://www.aseprite.org/)、[Krita](https://krita.org/) | 像素动画、角色和 UI 美术；Krita 也适合一般绘画 |
| 矢量图 | [Inkscape](https://inkscape.org/) | 图标、界面素材、SVG |
| 3D 建模与动画 | [Blender](https://www.blender.org/) | 模型、骨骼动画、材质和场景制作 |
| 音频编辑 | [Audacity](https://www.audacityteam.org/) | 剪辑、降噪、处理音效 |
| 免费起步素材 | [Kenney](https://kenney.nl/assets)、[OpenGameArt](https://opengameart.org/) | 原型和学习项目；下载前逐项确认授权、署名和商用条件 |

## 4. Godot 的框架与社区插件

Godot 插件常见两类：**编辑器插件**扩展工作流，**运行时插件**提供可放进游戏的功能。可以从[官方 Asset Library](https://godotengine.org/asset-library/asset)或项目自己的官方仓库寻找。下面是按用途整理的知名选项，不是官方背书或必装清单。

| 需求 | 可了解的项目 | 说明 |
|---|---|---|
| 行为树、状态机、复杂 AI | [LimboAI](https://github.com/limbonaut/limboai) | Godot 4 的社区 AI 插件，提供行为树与层级状态机；适合敌人 AI 变复杂后再引入 |
| 对话、视觉小说流程 | [Dialogic](https://github.com/dialogic-godot/dialogic) | 对话与视觉小说工具；当前主线 Dialogic 2 要求 Godot 4.5 或更新版本，仍需检查具体发行版兼容性 |
| 镜头跟随和切换 | [Phantom Camera](https://github.com/ramokz/phantom-camera) | 为 Camera2D / Camera3D 提供跟随、平滑移动和镜头切换等能力 |
| 自动化测试 | [GdUnit4](https://github.com/godot-gdunit-labs/gdUnit4)、[GUT](https://github.com/bitwes/Gut) | Godot 项目的测试框架。小练习可先用手动测试；团队或逻辑较复杂时再引入，并确认当前版本支持 |
| Steam 集成 | [GodotSteam](https://github.com/GodotSteam/GodotSteam) | 社区 Steamworks 绑定；需要处理 SDK、导出模板和平台构建，属于发布阶段的进阶集成 |
| 物理引擎 | Godot 内置物理后端 | 先用引擎提供的 2D / 3D 物理。Godot 4.4 起可在 3D 项目中选择 Jolt Physics 后端；不要把旧的独立插件教程直接当成当前必装方案 |

> **安装任何插件前先检查**：① 明确要解决的具体问题；② 项目页面标注支持的 Godot 版本；③ 最近是否仍有维护、文档和示例是否齐全；④ 授权、依赖和导出平台限制；⑤ 插件是否值得带来的维护成本。插件一般放在项目的 `addons/` 下，可在项目设置中启用；先在版本控制里提交或备份，再试装。

## 5. 本仓库的最小可用方案

1. 只学 GDScript：下载官网当前 stable 的标准版 Godot，使用内置脚本编辑器即可。
2. 想读本仓库的 C# 对照：选择 Godot .NET 版，另外准备 .NET SDK 和 C# 编辑器；官方示例的 [GDScript 版](https://github.com/godotengine/godot-demo-projects) 与 [C# 版](https://github.com/godotengine/godot-demo-projects/tree/master/mono) 都可在 GitHub 查看。
3. 创建 Git 仓库，先完成官方 2D 入门教程。
4. 只有在功能确实需要时，再添加插件、美术软件或构建工具。发布前再按目标平台准备导出模板与平台 SDK。

本仓库更具体的下载、素材和 C# 配置步骤见[教程总览的环境准备](./README.md#3-环境准备)。
