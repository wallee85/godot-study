## 3. 项目设置（一次配好，后面不返工）

### 3.1 渲染与像素画（**最关键的一项**）

菜单 `项目 → 项目设置`：

| 路径 | 值 | 为什么 |
|---|---|---|
| `显示 → 窗口 → 大小 → 视口宽度` | `320` | 低分辨率基准，让引擎放大 |
| `显示 → 窗口 → 大小 → 视口高度` | `240` | |
| `显示 → 窗口 → 拉伸 → 模式` | `Canvas items` | 按分辨率缩放整个画面 |
| `显示 → 窗口 → 拉伸 → 纵横比` | `Keep` | 保持比例不变形 |
| `渲染 → 渲染器 → 渲染方法` | `Forward+`（建项目时的默认） | 2D 用不上高级特性，但它最完整 |

> **为什么是 320×240**：棋盘 10×10 格 × 16 像素 = **160×160 像素**。在 320×240 的基准里，棋盘正好占一半宽、2/3 高。

### 3.2 碰撞图层命名

`项目 → 项目设置 → 图层名称 → 2D 物理`：

| 位 | 名字 |
|---|---|
| 1 | `blocking` |
| 2 | `pickup` |

> 设置完，Inspector 里的图层勾选框会**显示名字**而不是"第 1 层"，非常省命。

### 3.3 输入映射（Input Map）

| 动作名 | 绑定按键 |
|---|---|
| `move_left` | `A`、`←` |
| `move_right` | `D`、`→` |
| `move_up` | `W`、`↑` |
| `move_down` | `S`、`↓` |

操作步骤：输入框里输入名字 → 点「添加」→ 点右边 `+` → 选 `键` → 按下 `A` → 再点 `+` 加 `←`。

> Godot 的 Input Map 是**内建且唯一**的方案，而且**天然支持手柄/重映射**（以后加"玩家 2"就是再定义一组动作）。

### 4.1 制作流程（要重复 10 多次，背下来）

1. `场景 → 新建场景` → 点「其他节点」→ 选根节点类型（比如 `StaticBody2D`）。
2. 右键根节点 → **添加子节点** → 加 `Sprite2D`。
   - 选中 `Sprite2D` → 检查器 → `Texture` → 拖入对应图片。
   - `Offset` 不用管；图片 16×16，节点位置 `(0,0)` 表示**图中心在原点**。
3. 右键根节点 → 添加子节点 → `CollisionShape2D`（需要碰撞的才加）。
   - 检查器 → `Shape` → **新建 RectangleShape2D** → 展开 → `Size = (16, 16)`。
4. （拾取物要）检查器里勾 `Area2D` 的层级、`监控`/`可监控` 设置（见下表）。
5. 选中根节点 → 检查器 → `碰撞 → 图层/掩码` 勾好（见下表）。

### 4.2 楼层与外墙

| 场景 | 根节点 | 子节点 | layer | group |
|---|---|---|---|---|
| `floor.tscn` | `Sprite2D` | — | — | — |
| `outer_wall.tscn` | `StaticBody2D` | `Sprite2D` + `CollisionShape2D`(16×16) | `blocking` | — |
| `wall.tscn` | `StaticBody2D` + 脚本 `wall.gd` | `Sprite2D` + `CollisionShape2D`(16×16) | `blocking` | — |

> **地板为什么是光秃秃一个 `Sprite2D`**：玩家永远走在地板上，不需要检测。100 个地板省掉 100 个碰撞体。
> 注意：`floor.tscn` 的根节点**不要用 `Node2D` 再套一个 `Sprite2D`**——直接用 `Sprite2D` 当根，省一层。

### 4.3 道具（拾取物）：`Area2D` 家族

| 场景 | 根节点 | 子节点 | layer | group | 脚本字段 |
|---|---|---|---|---|---|
| `food.tscn` | `Area2D` + `pickup.gd` | `Sprite2D` + `CollisionShape2D`(12×12) | `pickup` | `food` | `amount = 10` |
| `soda.tscn` | `Area2D` + `pickup.gd` | 同上 | `pickup` | `food` | `amount = 20` |
| `exit.tscn` | `Area2D`（**无脚本**） | 同上 | `pickup` | `exit` | — |

`Area2D` 的三个关键勾选项（新手最容易搞混，**记这一句话**）：

| 属性 | 值 | 含义 |
|---|---|---|
| `监控 (Monitoring)` | **食物/苏打/出口：关**；玩家的检测器：**开** | "我**要检测**别人吗" |
| `可监控 (Monitorable)` | **食物/苏打/出口：开**；玩家的检测器：**关** | "我**能被**别人检测到吗" |
| `碰撞 → 图层` | 食物：`pickup` | 我属于哪层 |
| `碰撞 → 掩码` | 食物：不勾 | 我要检测哪层 |

> **为什么食物不用 `监控`**：食物不需要知道"谁踩到了我"——是**玩家的检测器**主动发现食物。所以食物只要"**可被检测**"就够了。关掉 `监控` 能省一堆无用计算。

### 4.4 角色：`CharacterBody2D`

| 场景 | 根节点 | 子节点 | 分组 |
|---|---|---|---|
| `player.tscn` | `CharacterBody2D` + `player.gd` | **`AnimatedSprite2D`**、`CollisionShape2D`(16×16)、**`PickupDetector`(`Area2D`)** | `player` |
| `enemy.tscn` | `CharacterBody2D` + `enemy.gd` | **`AnimatedSprite2D`**、`CollisionShape2D`(16×16) | `enemy` |

> ⚠️ **子节点名字必须和脚本里的一致**：本教程的代码写的是 `$AnimatedSprite2D`（不是 `$Sprite2D`），因为 [05 章](./05-动画与音效.md) 要用它播动画。你如果现在只想用静态图，就**建 `AnimatedSprite2D` 但先只放一帧**（或者把脚本里的 `$AnimatedSprite2D` 改成 `$Sprite2D`，**两边一起改**）。
> `player` 分组也是必须的——[04 章](./04-玩家与敌人-移动与回合制.md) 的敌人靠 `get_first_node_in_group("player")` 找到你。

**`player.tscn` 的两层碰撞设置**（这是本章唯一的难点）：

```
Player (CharacterBody2D)          ← 分组: player
│   碰撞 → 图层: blocking       掩码: blocking
├─ CollisionShape2D   (16×16)   ← 我是一堵"会动的实体"，别人射线能打到我
├─ AnimatedSprite2D             ← 负责画（05 章配动画）
└─ PickupDetector (Area2D)
     │   碰撞 → 图层: (不勾)     掩码: pickup
     │   监控: 开    可监控: 关
     └─ CollisionShape2D  (16×16)
```

> **为什么要单独一个 `PickupDetector` 子节点**，而不是让 Player 直接检测？
> 因为 Godot 里"**实体阻挡**"（`CharacterBody2D`）和"**区域检测**"（`Area2D`）是两种节点。**分层是 Godot 的惯例做法**：一个负责物理实体，一个负责拾取判定。而且这样还能顺手把拾取判定范围调小（比如 8×8），手感更好。

**C# 路线注意**：把上面所有 `xxx.gd` 换成 `xxx.cs`（重命名为 `Player.cs` 之类）。在 Godot 里**新建 C# 脚本**会自动生成 `.csproj` / `.sln`，不需要手动 `dotnet new`。

## 5. 主场景：`main.tscn`

```
Main (Node2D)                         [level.gd]
├─ Camera2D                            位置 (56, 56)
├─ Board (Node2D)                      [board_manager.gd] ← 棋盘与角色都生成在自己下面
└─ LevelUi (CanvasLayer)               [level_ui.gd]
   ├─ BlackOverlay (ColorRect)         铺满、黑色
   ├─ LevelLabel (Label)               居中，字号 24
   └─ FoodLabel (Label)                左下角
```

### 5.1 相机

算一下：棋盘内部格子 `x,y ∈ [0,7]`，每格 16 像素 → 世界坐标上格子中心是 `0, 16, 32, …, 112`。加上外面一圈墙（`-16` 和 `128`），棋盘的总范围是 `-24 … 136`，**中心 = (−24 + 136) / 2 = 56**。✓

> Godot 里**这些都不用**：可见范围由窗口大小（320×240）决定，`Camera2D` 的 `position` 就是"**屏幕正中对准的世界坐标**"，而且**没有 z 轴**。

### 5.2 UI

| 节点 | 类型 | 设置 |
|---|---|---|
| `BlackOverlay` | `ColorRect` | `布局 → 锚点预设 → 整个矩形`；`颜色 = 黑 (0,0,0,1)` |
| `LevelLabel` | `Label` | 锚点预设 `居中`；`水平对齐/垂直对齐 = 居中`；`主题覆盖 → 字体大小 = 24` |
| `FoodLabel` | `Label` | 锚点预设 `左下`；`偏移 左=8 上=-28`；字号 12；颜色浅黄 |

## 6. 第一个脚本：全局网格常量（**双语言对照**）

新建 `scripts/grid.gd`：

```gdscript
# GDScript —— scripts/grid.gd
class_name Grid
extends RefCounted
## 全局网格约定。class_name 让它可以被任何脚本直接用（不用 preload）。

const TILE := 16            # 一格 = 16 像素（与 16×16 素材 1:1）
const COLUMNS := 8          # 棋盘内部格子数（不含外墙）
const ROWS := 8

# 碰撞层：位掩码（1 << n 就是"第 n+1 层"）
const LAYER_BLOCKING := 1 << 0   # = 1
const LAYER_PICKUP := 1 << 1     # = 2

## 格子坐标 → 世界坐标（像素）
static func to_world(cell: Vector2i) -> Vector2:
	return Vector2(cell.x * TILE, cell.y * TILE)

## 世界坐标 → 格子坐标
static func to_cell(world: Vector2) -> Vector2i:
	return Vector2i(roundi(world.x / TILE), roundi(world.y / TILE))

## 外圈墙的格子坐标是否合法（用于判断"这一格是不是外墙"）
static func is_outer(cell: Vector2i) -> bool:
	return cell.x == -1 or cell.x == COLUMNS or cell.y == -1 or cell.y == ROWS
```

对应的 C#：

```csharp
// C# —— scripts/Grid.cs（.cs 文件的文件名就是类名）
public static class Grid
{
    public const int Tile = 16;
    public const int Columns = 8;
    public const int Rows = 8;

    public const int LayerBlocking = 1 << 0;
    public const int LayerPickup = 1 << 1;

    public static Vector2 ToWorld(Vector2I cell) => new(cell.X * Tile, cell.Y * Tile);

    public static Vector2I ToCell(Vector2 world)
        => new(Mathf.RoundToInt(world.X / Tile), Mathf.RoundToInt(world.Y / Tile));

    public static bool IsOuter(Vector2I cell)
        => cell.X == -1 || cell.X == Columns || cell.Y == -1 || cell.Y == Rows;
}
```

**两个语言的差异点**：

| 点 | GDScript | C# |
|---|---|---|
| 全局访问 | `class_name Grid` → 哪里都能写 `Grid.TILE` | `public static class Grid`（C# 本来就全局可见，但**必须放在项目里让它参与编译**） |
| 整数向量 | `Vector2i` | `Vector2I`（**大写的 I**） |
| 静态方法 | `static func` | `static` |
| 是否继承 Node | **不用**：`extends RefCounted`（一个纯数据类） | 不用继承任何东西 |
| 缩进/分号 | 缩进敏感、无分号 | 花括号、分号 |

> ⚠️ **GDScript 缩进是语法**。本教程的 GDScript 代码块**用 Tab 缩进**（Godot 编辑器默认），复制粘贴时如果被转成了空格，可能报 "unindented line" 之类的错。在 Godot 编辑器里粘贴会自动按你的设置转换。

> ⚠️ **C# 类必须 `partial` 吗**？只有**继承 `GodotObject` 的类**（也就是 `Node`、`Resource` 这些）才必须 `partial`。像 `Grid` 这样的纯静态类不用。

## 7. ⚠️ 一条重要规则：**一个节点只能挂一个脚本**

这意味着：**GDScript 和 C# 是"二选一"的路线**，不是"两种都写进去"。

- 你可以整个项目 **全 GDScript**（推荐入门）；
- 也可以整个项目 **全 C#**（推荐你这种 .NET 老手想复用生态时）；
- 甚至**混用不同文件/不同节点**（比如 UI 用 GDScript、逻辑用 C#），但跨语言调用很别扭，**不建议新手混**。

**本教程的处理方式**：每段代码给你两份，**你挑一条路线，从头到尾走完**。想两条都试，就建两个项目各走一遍（顺便能直观比较两种写法的体感）。
