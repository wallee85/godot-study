# 00 · Godot 核心概念地图

> **这一章不用敲代码**，只用来看懂"Godot 到底是怎么跑起来的"。

---

## 1. 节点类型与父子关系

Godot 使用节点树组织场景。每个节点都有明确职责，脚本可以扩展节点的行为：

```
Sprite2D（它自己就会画图）
StaticBody2D（它自己就会碰撞）
  └─ 挂上你的脚本（脚本"成为"这个节点的一部分，而不是挂在它上面）
```

### 1.1 场景节点示例

**Godot**：一个 `StaticBody2D` 节点（它自己就是"不会动的碰撞体"），下面挂两个子节点：

```
Wall  (StaticBody2D，挂 wall.gd)
├─ Sprite2D            ← 负责画
└─ CollisionShape2D    ← 负责碰撞形状（形状本身是一个 RectangleShape2D 资源）
```

> **关键洞察**：`CollisionShape2D` 是 `StaticBody2D` 的**子节点**，负责提供碰撞形状。节点通过父子关系组合起来。

## 2. 场景资源与实例化

场景可保存节点树，之后可在编辑器中组合，或在运行时创建实例。

| 场景文件 | 用途 |
|---|---|
| `main.tscn` | 主场景，组织棋盘、角色和界面 |
| `player.tscn` | 玩家节点及其子节点 |
| `wall.tscn` | 墙壁节点及其子节点 |

运行时载入并创建场景实例后，必须将节点加入场景树：

```gdscript
const PLAYER_SCENE := preload("res://scenes/player.tscn")

func spawn_player() -> void:
    var player := PLAYER_SCENE.instantiate()
    player.position = Vector2(0, 0)
    add_child(player)
```

```csharp
private static readonly PackedScene PlayerScene =
    GD.Load<PackedScene>("res://scenes/player.tscn");

private void SpawnPlayer()
{
    var player = PlayerScene.Instantiate<CharacterBody2D>();
    player.Position = Vector2.Zero;
    AddChild(player);
}
```

> `instantiate()` 创建的节点尚未进入场景树；调用 `add_child()` 后，它才会参与场景运行。

### 2.1 `.tscn` 是纯文本

```
[gd_scene load_steps=3 format=3]
[ext_resource type="Script" path="res://scripts/wall.gd" id="1"]
[node name="Wall" type="StaticBody2D"]
script = ExtResource("1")
[node name="Sprite2D" type="Sprite2D" parent="."]
texture = ExtResource("2")
```

**这带来一个实际好处**：出问题时可以直接**读文件**确认编辑器保存了什么。

## 3. 节点树与生命周期：Godot 什么时候调你的代码

**这是全教程最重要的一张图。**

```
add_child() / 场景加载
        │
        ▼
  _enter_tree()        ← 自顶向下（父先，子后）。此时还没进"就绪"状态
        │
        ▼
  _ready()             ← 自底向上（子先，父后）！
        │                  → 子节点在父节点 _ready 之前就已经准备好了
        │                  → 所以 @onready var x = $Child 一定拿得到
        │
  【主循环开始】
        │
        ├─ _process(delta)          ← 每渲染帧一次。输入（轮询）、逻辑、UI
        ├─ _physics_process(delta)  ← 固定步长（默认 60 次/秒）。物理、射线查询
        ├─ 物理信号（area_entered 等）在物理步里发出
        ├─ await 的代码在这些钩子之间恢复执行
        └─ _draw()                  ← 需要重绘时（手动绘制用）
        │
  【直到被移除 / 释放】
        │
  _exit_tree()         ← 从树里摘掉时调用一次
```

### 3.1 必须记住的几条

| 事实 | 说明 |
|---|---|
| **`_ready()` 是子先父后** | 所以父节点写 `@onready var board = $Board` 一定拿得到 |
| **`_ready()` 只调一次** | 节点被 `remove_child` 再 `add_child` 回来，`_ready` **不会**再跑（`_enter_tree` 会） |
| **物理查询只能在 `_physics_process` 里做** | 这是官方文档的硬规则（物理跑在独立线程时空间会锁）→ [04 章](./04-玩家与敌人-移动与回合制.md) 会用到 |
| **`free()` 是立刻释放** | 危险，除非你确定没有别的引用 |

### 3.2 "禁用"一个节点：`process_mode`

```gdscript
set_physics_process(false) # 只停 _physics_process
process_mode = Node.PROCESS_MODE_DISABLED   # 连子节点一起停
```

| `process_mode` | 含义 |
|---|---|
| `INHERIT`（默认） | 跟父节点一样 |
| `PAUSABLE` | 游戏暂停时停 |
| `WHEN_PAUSED` | 只在暂停时跑（做暂停菜单用） |
| `ALWAYS` | 永远跑（Autoload / 全局 UI 用） |
| `DISABLED` | 完全停 |

## 4. 序列化：`@export` 和 Inspector

Godot 的规则**更显式**：**只有标了 `@export` / `[Export]` 的才出现在 Inspector**。

```gdscript
# GDScript
@export var move_time := 0.1                    # 出现在 Inspector
@export_range(0.0, 1.0) var flicker: float = 0.2 # 带滑条范围
@export var chop_sounds: Array[AudioStream] = [] # 数组
@export var damage := 10
var hp := 4                                      # 没标 export → 不进 Inspector（≈ 纯运行时字段）
```

```csharp
// C#
[Export] public float MoveTime { get; set; } = 0.1f;
[Export(PropertyHint.Range, "0,1")] public float Flicker { get; set; } = 0.2f;
[Export] public Godot.Collections.Array<AudioStream> ChopSounds { get; set; } = new();
[ExportGroup("数值")]
[Export] public int Damage { get; set; } = 10;
private int _hp = 4;
```

### 4.1 复杂配置用 `Resource`

Godot 的做法是定义**自定义 Resource**（可以存成 `.tres` 文件、可以在多个场景间共享）：

```gdscript
# scripts/count_range.gd
class_name CountRange
extends Resource

@export var minimum := 1
@export var maximum := 5
```

```gdscript
# 用它
@export var wall_count: CountRange
```

## 5. signal：Godot 的一等公民（本章第二重要）

Godot 里官方推荐**用信号把"发生了什么事"广播出去**，谁关心谁自己接：

```gdscript
# game_manager.gd（广播方）
signal food_changed(food: int)

func spend_food(n: int) -> void:
    player_food_points -= n
    food_changed.emit(player_food_points)
```

```gdscript
# level_ui.gd（接收方）
func _ready() -> void:
    GameManager.food_changed.connect(_on_food_changed)

func _on_food_changed(food: int) -> void:
    $FoodLabel.text = "Food: " + str(food)
```

```csharp
// C# 广播方
[Signal] public delegate void FoodChangedEventHandler(int food);
EmitSignal(SignalName.FoodChanged, PlayerFoodPoints);

// C# 接收方
public override void _Ready() => GameManager.Instance.FoodChanged += OnFoodChanged;
private void OnFoodChanged(int food) => _foodLabel.Text = $"Food: {food}";
```

```csharp
```

原文自己也标注了"更好的做法是在 Canvas 上挂一个 UIManager"。**Godot 的信号就是那个"更好的做法"，而且是语言内建的**：

### 5.2 内建信号：不需要自己写

节点自带大量信号，比如：

| 节点 | 信号 |
|---|---|
| `Area2D` | `area_entered` / `body_entered` / `area_exited` / `body_exited` |
| `Button` | `pressed` |
| `Timer` | `timeout` |
| `AnimationPlayer` | `animation_finished` |
| `Tween` | `finished` |
| `SceneTree` | `process_frame` / `physics_frame` |

**这些就是 `await` 能用起来的原料**（见 §7）。

> **`await` 一个信号** = "等到这件事发生，再继续执行我后面的代码"。这是 Godot 最常用的流程控制手法。

## 6. 坐标与单位：Godot 里 1 单位就是 1 像素

所以我们要自己定一个约定：

```gdscript
# scripts/grid.gd —— 全局静态工具类
class_name Grid
extends RefCounted

const TILE := 16           # 一格 = 16 像素（和 16×16 的素材 1:1）
const COLUMNS := 8
const ROWS := 8

static func to_world(cell: Vector2i) -> Vector2:
    return Vector2(cell.x * TILE, cell.y * TILE)

static func to_cell(world: Vector2) -> Vector2i:
    return Vector2i(roundi(world.x / TILE), roundi(world.y / TILE))
```

```csharp
// C#
public static class Grid
{
    public const int Tile = 16;
    public const int Columns = 8;
    public const int Rows = 8;

    public static Vector2 ToWorld(Vector2I cell) => new(cell.X * Tile, cell.Y * Tile);
    public static Vector2I ToCell(Vector2 world) => new(Mathf.RoundToInt(world.X / Tile), Mathf.RoundToInt(world.Y / Tile));
}
```

`class_name Grid` 让这个类**全局可访问**（不用 `preload`），相当于 C# 的 `public static class`。

### 6.1 项目设置：让像素画不糊

| 设置路径 | 值 | 为什么 |
|---|---|---|
| `显示 → 窗口 → 大小 → 视口宽度/高度` | `320` / `240` | 像素游戏用**低分辨率基准**，让引擎自动放大 |
| `显示 → 窗口 → 拉伸 → 模式` | `Canvas items` | 按分辨率缩放整个画面 |
| `显示 → 窗口 → 拉伸 → 纵横比` | `Keep` | 保持比例，不拉伸变形 |

**为什么用 320×240 这么小的分辨率**：8×8 棋盘 + 一圈外墙 = 10×10 格 = **160×160 像素**。在 320×240 的基准分辨率里，棋盘占一半宽、2/3 高，留白正好。玩家显示器上由引擎放大 4~6 倍，像素依然锐利。

### 6.2 相机

Godot 的 `Camera2D` 语义很直观：**它的 `position` 就是"屏幕中心对准的世界坐标"**。

```gdscript
# main.tscn 里的 Camera2D
position = Vector2(56, 56)   # 棋盘中心：(3.5 格, 3.5 格) × 16 像素
```

> 想要棋盘看起来更大？调 `Camera2D.zoom`（`zoom = Vector2(2, 2)` 是放大 2 倍），但**建议用整数倍**，非整数倍会让像素抖动。

### 6.3 Godot 2D 的一个隐藏福利：Y-Sort

Godot 除了 `z_index`（-4096~4096，值大的在前）之外，还有一个 **Y 排序**：给父节点勾上 **`Y Sort Enabled`**，子节点就会**按 y 坐标自动排序**——y 大的（更靠下）画在后面。

```gdscript
# 勾选后，谁在屏幕上更靠下谁就更靠前 —— 2D 角色遮挡关系自动正确
$Actors.y_sort_enabled = true
```

## 7. `await`：语言内建的异步流程

Godot 可用 `await` 等待信号或异步操作完成：

```gdscript
# GDScript
func smooth_move(target: Vector2) -> void:
    var tween := create_tween()
    tween.tween_property(self, "position", target, move_time)
    await tween.finished                      # ← 等这个补间跑完
    position = target
```

```csharp
// C#
private async void SmoothMove(Vector2 target)
{
    var tween = CreateTween();
    tween.TweenProperty(this, "position", target, MoveTime);
    await ToSignal(tween, Tween.SignalName.Finished);
    Position = target;
}
```

### 7.1 能 `await` 什么

| 想等什么 | GDScript | C# |
|---|---|---|
| 下一渲染帧 | `await get_tree().process_frame` | `await ToSignal(GetTree(), SceneTree.SignalName.ProcessFrame)` |
| 下一物理帧 | `await get_tree().physics_frame` | 同上，`PhysicsFrame` |
| N 秒（受暂停影响） | `await get_tree().create_timer(1.0).timeout` | `await ToSignal(GetTree().CreateTimer(1.0), SceneTreeTimer.SignalName.Timeout)` |
| 任意信号 | `await node.some_signal` | `await ToSignal(node, Node.SignalName.SomeSignal)` |
| 补间结束 | `await tween.finished` | `await ToSignal(tween, Tween.SignalName.Finished)` |

1. **`await` 是语言语法**。任何函数都能 `await`，包括 `_ready()`；遇到等待点后，函数会在信号或异步操作完成时继续执行。
2. **`await` 可以拿到信号参数**。C# 侧还能使用 `Task` 并配合 `async` 生态。

> ⚠️ **坑**：`await` 之后节点可能已经被销毁了。Godot 的 `await` 在对象被 `queue_free()` 时会**直接中止**函数（安全），但如果你的对象只是被移出树，后面的代码照样跑 → 记得用 `is_instance_valid()` 检查。

## 8. 物理查询：使用 `intersect_ray`

根据对象类型选择合适的 Godot 物理节点：

Godot 里用 `Area2D`：

```gdscript
# player.tscn 里的子节点 PickupDetector (Area2D)
#   collision_mask = 2 (pickup 层)
func _ready() -> void:
    $PickupDetector.area_entered.connect(_on_pickup)

func _on_pickup(area: Area2D) -> void:
    if area.is_in_group("food"):
        eat_food(area.amount)
        area.queue_free()
```

**不需要刚体**，`Area2D` 之间互相检测是内建能力。

Godot 里每个 `CollisionObject2D` 都有两个 32 位字段：

| 字段 | 含义 | 类比 |
|---|---|---|
| `collision_layer` | **我属于哪些层**（我是谁） | 我身上贴的标签 |
| `collision_mask` | **我要检测哪些层**（我关心谁） | 我要找谁 |

**能不能碰撞，看的是"A 的 mask 有没有包含 B 的 layer"**（单向！双方都要互相检测时，两边的 mask 都得包含对方）。

本项目的分配：

| 对象 | layer | mask |
|---|---|---|
| Player / Enemy | `blocking` | 不关心（我们不用物理推进，只用射线查询） |
| Wall / OuterWall | `blocking` | — |
| Food / Soda / Exit | `pickup` | — |
| Player 的 PickupDetector | — | `pickup` |

```gdscript
# GDScript —— 注意：必须在 _physics_process 里调用
func probe(dir: Vector2i) -> Node2D:
    var space := get_world_2d().direct_space_state
    var query := PhysicsRayQueryParameters2D.create(
        global_position,
        global_position + Vector2(dir) * Grid.TILE,
        Grid.LAYER_BLOCKING,
        [get_rid()]                     # ← 把自己排除掉，不用关碰撞体
    )
    var result := space.intersect_ray(query)
    return result.get("collider") if result else null
```

```csharp
// C#
private Node2D Probe(Vector2I dir)
{
    var space = GetWorld2D().DirectSpaceState;
    var query = PhysicsRayQueryParameters2D.Create(
        GlobalPosition,
        GlobalPosition + new Vector2(dir.X, dir.Y) * Grid.Tile,
        Grid.LayerBlockingMask,
        new Godot.Collections.Array<Rid> { GetRid() });
    var result = space.IntersectRay(query);
    return result.Count > 0 ? result["collider"].As<Node2D>() : null;
}
```

使用射线查询时，注意以下规则：

> ⚠️ **硬规则**：`direct_space_state` **只能在 `_physics_process()` 里访问**（物理跑独立线程时空间会锁）。这就是 [04 章](./04-玩家与敌人-移动与回合制.md) 里玩家输入要"事件收 + 物理帧处理"两段式的原因。

> 💡 **`intersect_ray` 默认不检测 `Area2D`**（只检测 PhysicsBody）。想检测 Area 要设置 `collide_with_areas = true`。这正是我们想要的：**射线只被"挡路的东西"挡住，食物/出口（Area2D）不会挡路。**

## 9. 使用分组管理节点

Godot 的分组可以标记同类对象，并通过组名查找或批量调用节点：

```gdscript

add_to_group("food")

```

编辑器里也有 `节点 → 分组` 面板可以勾选。

## 10. UI：`Control` 节点 + `CanvasLayer`

Godot：UI 使用 `Control` 系节点，**锚点（Anchors）是 `Control` 自己的属性**。

常用锚点预设（编辑器里 `布局 → 锚点预设` 或代码设置）：

| 需求 | Godot |
|---|---|
| 全屏黑幕 | `set_anchors_preset(Control.PRESET_FULL_RECT)` |
| 左下角小字 | `PRESET_BOTTOM_LEFT` + `offset_left/top` |
| 屏幕居中 | `PRESET_CENTER` |

> **中文显示提醒**：Godot 4 默认字体只覆盖拉丁/西里尔等字形，**中文会显示成方框**。要在 UI 里显示中文，需要自己导入一个中文 TTF 并在 `Label` 上设 `Label Settings → Font`。本游戏 UI 全是英文（`Day 1` / `Food: 100`），不受影响。

## 11. 资源与文件系统：`res://` 与 UID

**git 要提交什么**：

```
✅ project.godot          工程配置
✅ *.tscn / *.tres        场景与资源
✅ *.gd / *.cs            脚本
✅ *.import               导入设置（很小，必须提交）
❌ .godot/                导入缓存，必须忽略
❌ *.exe / 导出产物
```

### 11.1 资源路径的两种写法

```gdscript
# ① preload：编译期确定路径 → 项目启动时加载，之后是零成本引用（推荐给固定资源）

# ② load：运行时按字符串加载（路径可变、或想延迟加载时用）
```

C# 里只有一种：**`GD.Load<T>("res://...")`**（没有 `preload` 的对应物）——所以 C# 项目里一般写成 `static readonly` 字段，靠静态初始化达到类似 `preload` 的效果。

## 14. 常见问题

**Q：我改了脚本，编辑器怎么没反应？**
A：保存脚本后检查「调试器 → 错误」面板；C# 项目需要点击「Build」完成编译。

**Q：`instantiate()` 出来的东西不显示。**
A：99% 是忘了 `add_child()`。它是"造出来了但不在世界里"。

**Q：覆盖 `_ready()` 后，基类的实现会自动运行吗？**
A：不会。需要执行基类逻辑时，在 GDScript 中显式调用 `super()`；C# 中则调用 `base._Ready()`。

**Q：`null` 判断怎么老是不对？**
A：见 [附录总览 §6.6](./README-原Roguelike主线.md#66-null-与已销毁对象)——用 `is_instance_valid()`，不要用 `== null`。

**Q：Godot 中只需要逻辑、不需要坐标的节点用什么？**
A：使用 `Node`；需要位置、旋转或缩放时使用 `Node2D`。
