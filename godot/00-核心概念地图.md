# 00 · Godot 核心概念地图（Dodge the Creeps 版）

> **这一章不用敲代码**，只看懂"Godot 到底是怎么跑起来的"。
> 后面每一章的概念都会在这里先露一次面。

---

## 1. 场景由节点组成

Godot 使用**节点树**组织游戏对象。每个节点都有明确职责，节点可以包含子节点，脚本则扩展节点的行为。

### 1.1 官方教程里的实例

**玩家的样子**（[官方 player.tscn](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/player.tscn)）：

```
Player (Area2D)              ← 根节点决定了"我是一个能检测重叠的区域"
├─ AnimatedSprite2D          ← 负责画（帧动画）
├─ CollisionShape2D          ← 负责碰撞形状
└─ Trail (GPUParticles2D)    ← 负责拖尾装饰
```

**关键洞察**：`CollisionShape2D` 是 `Area2D` 的**子节点**，负责提供碰撞形状。场景中的节点通过父子关系组合起来。

## 2. 场景资源与实例化

场景可以保存一棵节点树，并在其他场景中重复使用或由代码动态创建。

| 场景文件 | 用途 | 根节点 |
|---|---|---|
| [player.tscn](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/player.tscn) | 玩家 | `Area2D` |
| [mob.tscn](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/mob.tscn) | 敌人 | `RigidBody2D` |
| [hud.tscn](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/hud.tscn) | 界面 | `CanvasLayer` |
| [main.tscn](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/main.tscn) | 主场景 | `Node` |

官方教程在主场景中组合 `Player`、`Mob` 和 `HUD`：

> "In this project, we will make 3 independent scenes: `Player`, `Mob`, and `HUD`, which we will combine into the game's `Main` scene."

运行时创建节点时，需要把它加入场景树：

```gdscript
# GDScript —— 官方 main.gd 就是这么干的
var mob = mob_scene.instantiate()
add_child(mob)
```

```csharp
// C#
Mob mob = MobScene.Instantiate<Mob>();
AddChild(mob);
```

> ⚠️ **`add_child()` 是必须的**。`instantiate()` 出来的节点**不在树里**：不显示、不更新、不碰撞。

### 2.1 在编辑器里实例化场景

官方 05 节的做法：`Main` 场景里点 **「实例化（Instance）」** 按钮（链环图标）→ 选 `player.tscn`。

### 2.2 `.tscn` 是纯文本

官方两个版本的场景文件都是可以直接读的文本：

```
[gd_scene format=3 uid="uid://bwhlkliwp13p4"]
[ext_resource type="Script" path="res://player.gd" id="1"]
[node name="Player" type="Area2D" groups=["player"]]
script = ExtResource("1")
```

## 3. 节点树与生命周期

**这是全篇最重要的一张图。**

```
add_child() / 场景加载
        │
        ▼
  _enter_tree()        ← 自顶向下（父先，子后）
        │
        ▼
  _ready()             ← 自底向上（子先，父后）！
        │                  → 所以 @onready var x = $Child 一定拿得到
        │
  【主循环开始】
        │
        ├─ _process(delta)          ← 每渲染帧一次：输入轮询、移动、UI
        ├─ _physics_process(delta)  ← 固定步长（默认 60/秒）：物理、射线查询
        ├─ _input(event) / _unhandled_input(event)   ← 输入事件
        ├─ 物理信号在此发出（body_entered / screen_exited …）
        └─ Timer 的 timeout 信号按时间发出
        │
  【直到被移除 / 释放】
        │
  _exit_tree()         ← 从树里摘掉时调用一次
```

> ⚠️ **大小写写错不会报错，只是永远不被调用**。GDScript 是 `_ready`、C# 是 `_Ready`。

### 3.1 官方代码里能直接看到的两条

**① `_ready` 里拿视口尺寸**（[官方 player.gd](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/player.gd)）：

```gdscript
func _ready():
	screen_size = get_viewport_rect().size
	hide()
```

**② `_process` 里用参数 `delta` 做"每秒速度"**：

```gdscript
func _process(delta):
	position += velocity * delta
```

### 3.2 `_ready` 是"子先父后"意味着什么

`Main` 场景的结构是：

```
Main (Node)
├─ Player         ← 子节点先 _ready
├─ MobTimer
├─ HUD
└─ ...
```

所以 `Main._ready()` 跑的时候，`Player` / `HUD` 都已经就绪了。**官方 `main.gd` 的 `new_game()` 敢直接 `$Player.start(...)`、`$HUD.update_score(...)`，就是靠这条保证。**

## 4. `@export`：把变量搬进 Inspector

Godot 更显式：**只有标了 `@export` / `[Export]` 的才出现在 Inspector**。

```gdscript
# GDScript —— 官方 player.gd
@export var speed = 400    # How fast the player will move (pixels/sec).
```

```csharp
// C# —— 官方 Player.cs
[Export]
public int Speed { get; set; } = 400; // How fast the player will move (pixels/sec).
```

官方教程对这件事的解释（翻译）：

> 在第一个变量 `speed` 上用 `export` 关键字，可以让我们在 Inspector 里设置它的值。**如果你在 Inspector 里改了值，它会覆盖脚本里的默认值（脚本本身不会被修改）。**

> ⚠️ **C# 专属**：**新增 `[Export]` 变量后必须点编辑器右上角的「Build」**，否则 Inspector 里根本看不到它。官方教程专门画了图警告这一条（[README §4](./README.md#4-️-c-专属注意事项这节比代码更重要)）。

### 4.1 复杂配置用 `Resource`

本教程用不上，但官方成品里的 **`SpriteFrames` 就是一个 `Resource`**——它把"几组帧序列"打包成一个可复用资产，被 `AnimatedSprite2D` 引用（[02 章](./02-玩家场景.md)）。

## 5. signal：Godot 的一等公民（**本章第二重要**）

Godot 官方推荐**用信号把"发生了什么事"广播出去**，谁关心谁自己接。

### 5.1 官方代码里的 5 个信号（全是这套思路）

| 信号 | 声明在哪 | 谁发出 | 谁接收 |
|---|---|---|---|
| `hit` | `player.gd`（**自定义**） | 玩家被撞到时 | `main.gd` → `game_over()` |
| `start_game` | `hud.gd`（**自定义**） | 点 Start 按钮 | `main.gd` → `new_game()` |
| `body_entered` | `Area2D`（**内建**） | 有物体进入区域 | `player.gd` → `_on_body_entered()` |
| `screen_exited` | `VisibleOnScreenNotifier2D`（**内建**） | 敌人离开屏幕 | `mob.gd` → `queue_free()` |
| `timeout` | `Timer`（**内建**） | 计时结束 | `main.gd` / `hud.gd` |

```gdscript
# GDScript —— 自定义信号（官方 player.gd）
signal hit
...
hit.emit()
```

```csharp
// C# —— 自定义信号（官方 Player.cs）
[Signal]
public delegate void HitEventHandler();
...
EmitSignal(SignalName.Hit);
```

```gdscript
# GDScript —— 连信号（官方 main.gd 里是编辑器连的，等价代码写法：）
$Player.hit.connect(game_over)
```

```csharp
// C# —— 等价代码写法
GetNode<Player>("Player").Hit += GameOver;
```

### 5.2 两种连线方式（官方都用了）

| 方式 | 怎么做 | 优点 |
|---|---|---|
| **编辑器连线** | 选中节点 → 「节点」面板 → 双击信号 → 选接收节点 → 选方法 | 直观、可见（存在 `.tscn` 里） |
| **代码连线** | `node.signal_name.connect(方法)` | 灵活、可动态连断 |

> ⚠️ **C# 的坑**：编辑器里连信号时，**方法名要手打且必须完全正确**（`OnBodyEntered`，不是 `on_body_entered`）。官方原话："Be careful to type the method names precisely when connecting signals."

官方 `main.gd` 里那句 `get_tree().call_group(&"mobs", &"queue_free")` 也是同一思路的另一种用法：**广播给"所有敌人"，不关心有几个、是谁。**

## 6. 坐标与像素：Godot 里 1 单位 = 1 像素

`Node2D.position` 表示节点在 2D 场景中的像素坐标。玩家场景中的精灵通过 `scale` 调整显示大小。

### 6.1 本项目（官方）的分辨率约定

| 设置 | 值 | 为什么 |
|---|---|---|
| 视口宽 × 高 | **480 × 720** | 官方："This game is designed for portrait mode"（竖屏） |
| 拉伸模式 | `canvas_items` | 按分辨率缩放整个画面 |
| 纵横比 | `keep` | 保持比例不变形 |

于是"屏幕边界"就是 `Vector2(480, 720)`——**这就是官方 `player.gd` 里 `screen_size` 的全部含义**。

### 6.2 官方成品里的 z 顺序技巧

| 节点 | `z_index` | 效果 |
|---|---|---|
| `Player` | **10** | 玩家永远画在敌人上面 |
| `Player/Trail` | **-1** | 拖尾画在玩家**下面** |
| `Main/ColorRect` | 默认（0），但它是 `Main` 的**第一个**子节点 | 背景画在所有东西后面 |

> **同级节点，树上越靠后的画在越上面**；`z_index` 数字大的画在上面。通常按绘制顺序安排节点即可，需要时再调整 `z_index`。

## 7. 物理：先选节点，再谈参数

> **官方对 `Area2D` 的选择专门解释了一句**（翻译）：
> "Godot 也提供了 `CharacterBody2D`，专门为 2D 角色设计……**在很多真实项目里，`CharacterBody2D` 会是玩家和敌人的更好选择。但本教程聚焦于能适用于更广泛节点的核心概念。**"
> 记住这句话：[附录-回合制Roguelike](./附录-回合制Roguelike/README-原Roguelike主线.md) 用的就是 `CharacterBody2D` 路线。

Godot 的 `Area2D` **不需要刚体**：它订阅 `body_entered`（检测物理实体）或 `area_entered`（检测其他区域）就行。

```gdscript
# GDScript —— 官方 player.tscn 里连的是这个
func _on_body_entered(_body):
	hide()
	hit.emit()
	$CollisionShape2D.set_deferred(&"disabled", true)
```

每个 `CollisionObject2D` 有两个 32 位字段：

| 字段 | 含义 | 类比 |
|---|---|---|
| `collision_layer` | **我属于哪些层** | 我贴的标签 |
| `collision_mask` | **我要检测哪些层** | 我要找谁 |

**能不能互相检测，看的是"A 的 mask 有没有包含 B 的 layer"（单向！）**

官方在这个项目里做了一个**很值得学的设置**：

| 节点 | layer | mask | 目的 |
|---|---|---|---|
| `Mob` | 1（默认） | **`0`（全不勾）** | **官方原话**：这样"确保敌人之间不会互相碰撞" |
| `Mob` 的 `gravity_scale` | — | **`0`** | 防止敌人往下掉 |
| `Player`(Area2D) | 1 | —（Area2D 用自己的检测逻辑） | 玩家要能检测到敌人 |

### 7.1 `set_deferred`：为什么不能直接改

官方代码里这行有一句很重要的注释：

```gdscript
# Must be deferred as we can't change physics properties on a physics callback.
$CollisionShape2D.set_deferred(&"disabled", true)
```

翻译：**在物理回调（`body_entered` 这种）里，不能直接修改物理属性**，必须"延迟到本次物理计算结束后再改"。

| 写法 | 结果 |
|---|---|
| `$CollisionShape2D.disabled = true` | ❌ 报错 / 行为未定义（在物理回调里） |
| `$CollisionShape2D.set_deferred(&"disabled", true)` | ✅ 安全 |

```csharp
// C# 官方写法
GetNode<CollisionShape2D>("CollisionShape2D").SetDeferred(CollisionShape2D.PropertyName.Disabled, true);
```

> **这是 Godot 版的"`Destroy` 是延迟到帧末"的同类知识**：引擎有"某些操作不能在某个时机做"的硬规则，**违反时报错信息往往很隐晦**。记住两条：
> ① 物理回调里不能改物理属性 → `set_deferred`
> ② `direct_space_state`（射线查询）只能在 `_physics_process` 里访问

## 8. 输入：两套写法都要会

| 写法 | 代码 | 特点 | 官方用在哪 |
|---|---|---|---|
| **轮询** | `Input.is_action_pressed("move_right")` | 每帧问一次"现在按着吗" | **`player.gd` 的 `_process`** |
| **事件** | `_input(event)` / `_unhandled_input(event)` | 按键发生时才通知 | 按钮、菜单、快捷键 |

```gdscript
# GDScript —— 官方 player.gd 的轮询写法
if Input.is_action_pressed(&"move_right"):
	velocity.x += 1
```

```csharp
// C# —— 官方 Player.cs
if (Input.IsActionPressed("move_right"))
{
    velocity.X += 1;
}
```

**动作名从哪来**：`项目设置 → 输入映射`（Input Map）里定义 `move_left` / `move_right` / `move_up` / `move_down`。

## 9. Timer 节点 与 `await`

官方用了 4 个 `Timer` 节点（`MobTimer` / `ScoreTimer` / `StartTimer` / `MessageTimer`）：

| 属性 | 官方取值 | 含义 |
|---|---|---|
| `wait_time` | 0.5 / 1 / 2 / 2 | 多久触发一次 |
| `one_shot` | `StartTimer`、`MessageTimer` **开** | 只触发一次 |

```gdscript
# 节点式（官方 main.gd）
$StartTimer.start()
$MobTimer.stop()
```

**另一种做法是 `await`**（官方 `hud.gd` 用了）：

```gdscript
# GDScript —— 官方 hud.gd
await $MessageTimer.timeout
await get_tree().create_timer(1).timeout
```

```csharp
// C#
await ToSignal(messageTimer, Timer.SignalName.Timeout);
await ToSignal(GetTree().CreateTimer(1.0), SceneTreeTimer.SignalName.Timeout);
```

| 想干什么 | 用 Timer 节点 | 用 await |
|---|---|---|
| 周期性做事（每 0.5 秒生成敌人） | ✅ 更自然 | 要写循环 |
| 按顺序等待（显示完 A 再显示 B） | 很别扭 | ✅ 代码从上到下读，最清楚 |

> **`await` 不是"协程"**，它就是语言自带的异步语法。`await 一个信号` = "等到这件事发生，再继续执行我后面的代码"。
> **官方 `show_game_over()` 就是最好的例子**：显示"Game Over" → 等计时器 → 换文字 → 等 1 秒 → 显示按钮。用 `await` 写成了一条直线，用回调就散了。

## 11. UI：`Control` 与 `CanvasLayer`

官方 `HUD` 的结构（[hud.tscn](https://github.com/godotengine/godot-demo-projects/blob/master/2d/dodge_the_creeps/hud.tscn)）：

```
HUD (CanvasLayer)
├─ ScoreLabel (Label)        锚点「顶部宽」，字号 60，居中
├─ MessageLabel (Label)      锚点「居中」，字号 60
├─ StartButton (Button)      锚点「底部居中」，偏移 -200 ~ -100
└─ MessageTimer (Timer)      one_shot = 开
```

> **`CanvasLayer` 的作用**：官方解释是"让 UI 元素画在游戏画面之上，**不会被玩家或敌人盖住**"。
> **UI 内部的顺序**：同级节点树上的顺序就是绘制顺序——所以 `ColorRect` 背景必须放在 `Main` 的**第一个**子节点位置。

## 12. 使用分组管理节点

分组可以为节点添加分类标记，并通过组名一次性调用所有成员的方法。官方项目用它标记玩家与敌人：

```gdscript
# ① 给玩家打标记（player.tscn 里设的）
# ② 给敌人打标记（mob.tscn 里设的 groups=["mobs"]）

# 然后一次性清空所有敌人（官方 main.gd）
get_tree().call_group(&"mobs", &"queue_free")
```

```csharp
// C# 官方写法：注意方法名常量
GetTree().CallGroup("mobs", Node.MethodName.QueueFree);
```

> **这是"重新开始游戏"的核心机制**：不用维护一个 `List<Mob>`，一句广播就把场上的敌人全清了。

## 14. 常见问题

**Q：我改了脚本，编辑器怎么没反应？**
A：保存脚本后检查编辑器的「调试器 → 错误」面板。C# 项目需要先点击「Build」完成编译。

**Q：`instantiate()` 出来的东西不显示。**
A：99% 是忘了 `add_child()`。

**Q：`null` 判断怎么老是不对？**
A：用 `is_instance_valid()` / `GodotObject.IsInstanceValid()`，**别用 `== null`**。

**Q：Godot 的"空节点"用什么？**
A：`Node2D`（有位置）或 **`Node`（纯逻辑容器）**。官方 `Main` 就用 `Node`，理由官方说了：*"这个节点只是游戏逻辑的容器，本身不需要 2D 功能"*。
