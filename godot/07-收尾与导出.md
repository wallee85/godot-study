## 1. 换个背景色

官方原话（翻译）：

> 默认的灰色背景不太好看，我们改个颜色。一个办法是用 **`ColorRect`** 节点。**把它放在 `Main` 下的第一个节点位置，这样它会被画在其它节点后面**。
> `ColorRect` 只有一个属性：**`Color`**。选一个你喜欢的颜色，然后选 **`布局 → 锚点预设 → 整个矩形 (Full Rect)`**，让它铺满屏幕。

### 1.1 操作

1. 打开 `main.tscn`
2. 选中 **`Main`** → `Ctrl+A` → 搜索 **`ColorRect`** → 创建
3. **把它拖到子节点列表的【最上面】**（在「场景」面板里拖动节点）
4. 检查器 → **`颜色 (Color)`** → 点色块 → 选一个颜色
   - 官方成品用的是 `Color(0.219608, 0.372549, 0.380392, 1)`（一个偏灰的青绿色）
5. 检查器 → **「布局」→「锚点预设」→ `整个矩形 (Full Rect)`**

### 1.2 ✅ 检查点

- 「场景」面板里 **`ColorRect` 是 `Main` 的第一个子节点**
- **`F5` 运行时，背景是你选的颜色**，而且**玩家和敌人画在背景上面**（不是被背景盖住）

> 🔴 **为什么必须放第一个**：Godot 里**同级节点，树上靠后的画在越上面**。
> 放错位置 → **背景把玩家和敌人都盖住了**，你会以为"游戏坏了"。
>
> **官方还提到**：*"如果你有背景图，可以用 `TextureRect` 代替 `ColorRect`。"*
>
> **对照 Unity**：Unity 里你会改 `Camera.backgroundColor` 或加一个 `Image`。
> **Godot 的相机根本不管背景**——`Camera2D` 没有背景色属性，**背景就是"场景里画在最底下的那个节点"**。这是观念差异：**Godot 的绘制是纯粹的节点顺序。**

## 2. 加音乐和音效

素材里有两个音频：

| 文件 | 用途 |
|---|---|
| `art/House In a Forest Loop.ogg` | 背景音乐（**要循环**） |
| `art/gameover.wav` | 死亡音效 |

### 2.1 添加两个播放器节点

1. 选中 `Main` → `Ctrl+A` → 搜索 **`AudioStreamPlayer`** → 创建 → 改名 **`Music`**
2. 再来一次 → 改名 **`DeathSound`**
3. 对每一个：检查器 → **`流 (Stream)`** → 点 `[empty]` → **「加载 (Load)」** → 选对应文件

| 节点 | Stream |
|---|---|
| `Music` | `art/House In a Forest Loop.ogg` |
| `DeathSound` | `art/gameover.wav` |

### 2.2 让背景音乐循环（**有个坑**）

官方原话（翻译）：

> **所有音频导入时都默认关闭了 `Loop`**。如果你想让音乐无缝循环：**点 `Stream` 文件右侧的箭头 → 选 `Make Unique`**，**然后**点开那个 Stream 文件，**勾上 `Loop`。**

**操作**：

1. 选中 `Music` 节点
2. 检查器 → `Stream` 属性右边有一个**下拉箭头**（或右键该属性）→ 选 **「设为唯一 (Make Unique)」**
3. 现在 `Stream` 里是一个**独立的副本**了 → **点开它**（点资源名字进入它的属性）
4. 找到 **`循环 (Loop)`** → **勾上**

**为什么要先 `Make Unique`**：直接改导入资源的 `Loop` 会**影响所有用到这个文件的地方**（游戏里其它地方也许需要不循环的版本）。`Make Unique` = "**就地做一个专用副本**"，只影响这一个节点。

> **对照 Unity**：Unity 里循环是 `AudioSource.loop = true`（**在播放器上**，不在资源上）。Godot 把这个设置放在**资源**上，所以才有"要改资源就得先 Make Unique"这一步。
> **记住这个操作**：以后任何"想改某处引用的资源、又不想影响别处"的场景，都是**箭头/右键 → Make Unique**。

### 2.3 恢复代码里的播放调用

[05 章 §8](./05-主场景.md#8-临时验证可选但推荐现在做一次) 里你把 `$Music` / `$DeathSound` 那几行注释掉了，**现在取消注释**。

代码里应该长这样（**这两行本来就在 [05 章](./05-主场景.md) 的代码里**）：

```gdscript
func new_game():
	...
	$Music.play()

func game_over():
	...
	$Music.stop()
	$DeathSound.play()
```

```csharp
// C#
public void NewGame()
{
    ...
    GetNode<AudioStreamPlayer>("Music").Play();
}

public void GameOver()
{
    ...
    GetNode<AudioStreamPlayer>("Music").Stop();
    GetNode<AudioStreamPlayer>("DeathSound").Play();
}
```

> **音乐用 `Music.stop()` 而不是 pause**：死亡时音乐要停，重开始时 `play()` 会**从头播**（`pause()` 会从暂停处继续，一般不是你要的效果）。

### 2.4 ✅ 检查点

- `main.tscn` 里有 `Music` 和 `DeathSound` 两个 `AudioStreamPlayer`
- `Music.Stream` 是一个**独立副本**，且 **`Loop` 已勾上**
- 代码里的 `$Music` / `$DeathSound` / `GetNode<AudioStreamPlayer>(...)` **都恢复了**
- **`F5`：点 Start 后有背景音乐；死亡时音乐停 + 播放 game over 音效**

## 4. 导出：把游戏变成能发给别人的东西

### 4.1 先装导出模板（**只需做一次**）

Godot 的**编辑器不带导出功能所需的模板**，要先下载：

1. 菜单 **`编辑器 → 管理导出模板`**（Editor → Manage Export Templates）
2. 点 **「下载并安装」**（Download and Install）——耐心等，几百 MB
3. 装完关掉窗口

> **模板是"按引擎版本"的**：4.7.2 的编辑器只能配 4.7.2 的模板。如果你升级了 Godot，要重下一次。
> **如果你点「项目 → 导出」时提示"没有导出模板"**，就是这一步没做。

### 4.2 导出 Windows 版

1. 菜单 **`项目 → 导出`**（Project → Export）
2. 点左上角 **「添加…」**（Add…）→ 选 **`Windows Desktop`**
3. 右侧一堆选项，**关键的几个**：

| 选项 | 建议 |
|---|---|
| **导出路径 (Export Path)** | 比如 `build/DodgeTheCreeps.exe` |
| `嵌入 PCK (Embed PCK)` | **勾上** → 只生成一个 exe，**方便发送** |
| `二进制格式 (Binary Format)` | 勾上（体积小、加载快） |

4. 点 **「导出项目 (Export Project)」**

**产物**：`DodgeTheCreeps.exe`。**双击就能玩，不需要装 Godot。**

> 💡 **发布给别人时**建议打个 zip，里面放 exe + 一个 `README.txt`（说明操作方式：方向键移动、点 Start 开始）。

### 4.3 导出 Web（网页）版 —— **仅限 GDScript 路线**

1. `项目 → 导出` → 「添加…」→ 选 **`Web`**
2. 导出路径填 `build/web/index.html`
3. 点「导出项目」

**产物**：`index.html` + `.wasm` + `.js` + `.pck` —— **必须放在服务器上才能玩**（直接双击 `index.html` 不行，浏览器 `file://` 协议有限制）。

**本地测试最简单的方法**（用 Python 起个静态服务器）：

```powershell
python -m http.server 8000 --directory .\build\web
```

然后浏览器打开 **`http://localhost:8000`**。

| 关键点 | 说明 |
|---|---|
| 依赖 | 浏览器需要支持 **WebAssembly + WebGL 2.0**（现代浏览器都行） |
| 单线程 vs 多线程 | 从 **Godot 4.3 起默认单线程导出**——**不需要** `SharedArrayBuffer`、**不需要**服务端配 COOP/COEP 跨域隔离头，**能直接上 itch.io / Poki / CrazyGames 这类平台** |
| 性能 | 浏览器里性能低于原生（官方在示例仓库里也提醒过） |

## 5. ⚠️ 正题：**C# 项目不能导出 Web**

**结论：对，用 C# 就做不了浏览器版游戏（Godot 4.x 全系列，含 4.7.2）。**

**官方文档原文**（[C# platform support](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html#c-platform-support)）：

> **Currently, projects written in C# cannot be exported to the web platform. To use C# on that platform, consider Godot 3 instead.**

翻译：

> **目前，用 C# 写的项目无法导出到 Web 平台。想在 Web 平台上用 C#，请考虑改用 Godot 3。**

### 5.1 为什么不行

Godot 4 的 C# 支持方式是"**把 .NET 运行时嵌进引擎进程**"里跑。而 Web 导出的产物要跑在**浏览器的 WASM 沙箱**里——**Godot 4 没有把 .NET 运行时做成可跑在 WASM 里的版本**。

有意思的是：**Godot 3.x 反而可以**（当年 Mono 提供了 WASM 支持），所以官方文档的建议是"退回 Godot 3"——那是个**已停止功能开发的老版本**，只适合确实需要"C# + 网页"的场景。

> 参考：[Platform state in C# for Godot 4.2](https://godotengine.org/article/platform-state-in-csharp-for-godot-4-2/#web)（官方博客，专门解释这件事）

### 5.2 各平台导出一览（**官方文档的准确说法**）

| 平台 | GDScript | C# |
|---|---|---|
| Windows / Linux / macOS | ✅ | ✅（Godot 4.2 起支持**全部桌面平台**） |
| Android | ✅ | ⚠️ 官方标注 **experimental（实验性）** |
| iOS | ✅ | ⚠️ **experimental + 额外限制**：官方导出模板的 iOS 模拟器**只支持 x64 架构**；**导出 iOS 只能在 macOS 上做** |
| **Web（浏览器）** | ✅ | ❌ **不能** |
| 主机（Switch / PS / Xbox） | ❌ 无官方导出 | ❌ 无官方导出 |

### 5.3 那怎么办？三条路

| 方案 | 说明 | 适合 |
|---|---|---|
| **① 用 GDScript 重写** | **最现实**。C# 绑定**就是照着 GDScript API 设计的**，两边的类和函数几乎一一对应（本项目每一章都在做这件事），小游戏重写成本通常不高 | 就是想要网页版 |
| ② 用 Godot 3 + C# | 能导 Web，但引擎老旧、生态萎缩、放弃 4.x 新特性 | 只此一条路时 |
| ③ 放弃 Web，做桌面版 | 桌面端 C# 完整支持 | 本来就不需要网页 |

### 5.4 一句话总结（**给未来的自己**）

> **想做网页游戏 → 从第一天就用 GDScript。**
> **想用 C# 的 .NET 生态（NuGet、xUnit、`async`/`await`）→ 桌面/移动可以，网页永远不行。**
>
> 这个限制**不是配置问题、不是等一个开关就能解决**——是运行时架构决定的。
> 所以**在项目开始时就要决定语言**，中途换语言的成本比一开始就选对高得多。

## 6. `.gitignore`（工程化收尾）

### 6.1 git 要提交什么 / 忽略什么

**提交**：

```
✅ project.godot          工程配置
✅ *.tscn / *.tres        场景与资源
✅ *.gd / *.cs            脚本
✅ *.import               导入设置（很小，必须提交！）
✅ art/ fonts/            原始素材
```

**忽略**：

```
❌ .godot/                导入缓存（会自动重建）
❌ export/ build/         导出产物
❌ *.exe *.pck *.zip
```

> **一句话对照 Unity**：Unity 提交 `Assets/ ProjectSettings/ Packages/`、忽略 `Library/ Temp/`；
> Godot 提交工程目录、忽略 `.godot/`。**规则一样，只是名字不同。**

### 6.2 推荐的 `.gitignore`

官方 `dodge_the_creeps` 项目的 `.gitignore` **只有一行**：

```
.godot/
```

**推荐你用这个完整版**：

```gitignore
# Godot 4 导入缓存（必须忽略，会自动重建）
.godot/

# 导出产物
export/
build/
*.exe
*.pck
*.zip

# 系统 / 编辑器
.DS_Store
Thumbs.db
.vscode/
.idea/

# C# 项目（可选：有人提交、有人不提交）
# bin/
# obj/
```

> **`project.godot` 会自己带一个 `.gitignore`**（[01 章 §1.2](./01-项目设置.md#12-点新建项目) 里"版本控制元数据"选了 Git 就会生成）。可以先把那段内容合并进来。

1. **改动成品来学**：拿官方示例项目直接乱改，比从零写更快看清"我改的东西起了什么作用"。
2. **遇到"Godot 里怎么干 X"**：先查 [类参考手册](https://docs.godotengine.org/en/stable/classes/index.html)——每个类都有信号/属性/方法列表 + 可运行示例。
3. **C# 路线随时翻** [C# API differences to GDScript](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_differences.html)——踩坑时能省很多时间。
4. **别急着只用 C#**：官方示例 95% 是 GDScript，社区答案也是。**会读 GDScript 是 Godot 的硬技能**，写可以选 C#。
