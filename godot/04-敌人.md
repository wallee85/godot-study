# 04 · 敌人（搭出 `mob.tscn`）

> 官方对应节：[Creating the enemy](https://docs.godotengine.org/en/stable/getting_started/first_2d_game/04.creating_the_enemy.html)
> 敌人行为很简单：**从屏幕边缘生成 → 选一个方向 → 直线飞出去 → 飞出屏幕就消失**。
> 本章第一次接触 `RigidBody2D` 和"真物理"。

---

## 0. 本章导航

| | |
|---|---|
| **开始时** | `player.tscn` 完成、能动（[03 章](./03-玩家脚本.md) 完成） |
| **结束时** | `mob.tscn`：会飞、离屏自动消失、能被玩家的判定框检测到 |
| **耗时** | 25~35 分钟 |
| **产出** | `mob.tscn` + `mob.gd` / `Mob.cs` |

**最终结构**：

```
Mob (RigidBody2D)                     ← 根节点，注册进分组 "mobs"
├─ AnimatedSprite2D                   ← 3 套动画，随机播一个
├─ CollisionShape2D                   ← 胶囊形，旋转 90°
└─ VisibleOnScreenNotifier2D          ← 离开屏幕时发信号
```

---

## 1. 新建场景 + 选根节点

1. 菜单 **`场景 → 新建场景`**
2. `Ctrl+A` → 搜索 **`RigidBody2D`** → 创建
3. **双击节点名**改成 **`Mob`**
4. `Ctrl+G` **编组子节点**（和 [02 章 §2](./02-玩家场景.md#2-锁定子节点官方提醒的省命操作) 一样，避免误触）

**为什么玩家用 `Area2D`、敌人用 `RigidBody2D`**：

| | 玩家 | 敌人 |
|---|---|---|
| 选什么 | `Area2D` | **`RigidBody2D`** |
| 为什么 | 位置**完全由按键决定**，不需要物理推动 | 需要"被赋予速度后**自己飞出去**"——这正是物理引擎的工作 |

---

## 2. 加三个子节点

选中 `Mob`，逐个 `Ctrl+A` 添加：

| 子节点 | 类型 | 作用 |
|---|---|---|
| `AnimatedSprite2D` | `AnimatedSprite2D` | 画 + 动画 |
| `CollisionShape2D` | `CollisionShape2D` | 碰撞形状 |
| **`VisibleOnScreenNotifier2D`** | `VisibleOnScreenNotifier2D` | **离开屏幕时发出信号**（用来清理自己） |

> **`VisibleOnScreenNotifier2D` 是干什么的**：它就是一个"**屏幕可见性检测器**"。节点进出屏幕时会发 `screen_exited` / `screen_entered` 信号。
> **对照 Unity**：Unity 里对应的是 `MonoBehaviour` 的**魔法方法** `OnBecameInvisible()` / `OnBecameVisible()`。**Godot 里它是一个可拖拽的节点 + 信号**——更显式、更可控（比如你可以给它设个矩形范围）。

## 3. 三个关键设置（**都影响玩法，别漏**）

### 3.1 关掉重力（`Gravity Scale = 0`）

1. 选中 **`Mob`** 根节点
2. 检查器 → **`RigidBody2D → 重力缩放 (Gravity Scale)`**
3. 设成 **`0`**

官方原话（翻译）：*"这会**防止敌人往下掉**。"*

> ⚠️ **`RigidBody2D` 默认受重力！** 不改的话，敌人会像石头一样往下坠——你会看到所有敌人都在屏幕底部堆积。

### 3.2 让敌人不互相碰撞（**取消 `Mask` 的勾选**）

1. 还在 `Mob` 节点上 → 检查器 → **`碰撞 (Collision) → 碰撞 → 遮罩 (Mask)`**
2. **取消勾选第 `1` 项**

官方原话（翻译）：*"这会**确保敌人之间不会互相碰撞**。"*

**为什么**：不取消的话，敌人撞在一起会互相弹开、堆成一团，看起来像"物理 bug"。

**理解一下 Godot 的图层机制**（和 Unity 差别很大）：

| 属性 | 含义 | 类比 |
|---|---|---|
| `Layer`（图层） | **我属于哪些层** | 我贴的标签 |
| `Mask`（遮罩） | **我要检测哪些层** | 我要找谁 |

**能不能碰撞，看的是"A 的 mask 有没有包含 B 的 layer"——单向的！**

| 谁 | Layer | Mask | 结果 |
|---|---|---|---|
| `Mob` | 1（默认，**不动**） | **0（全不勾）** | 不检测任何东西 → **不和别的敌人碰撞** |
| `Player`（`Area2D`） | 1 | — | **照样能检测到敌人**（玩家那一侧没关） |

> **对照 Unity**：同样的事要在 `Project Settings → Physics 2D → Layer Collision Matrix` 里取消勾选——**那是全局的、两个方向一起关**。
> **Godot 更精确**：可以表达"敌人不撞敌人，但玩家能撞敌人"这种**非对称关系**，**在节点上就能设**。

### 3.3 ✅ 检查点

- `Mob.Gravity Scale = 0`
- `Mob.Collision → Mask` 里 **第 1 项没有勾**

## 4. 做 3 套动画

### 4.1 创建 SpriteFrames

1. 选中 `AnimatedSprite2D`
2. 检查器 → **`动画 → 精灵帧`** → `[empty]` → **「新建 SpriteFrames」**
3. **点一下这个 `SpriteFrames`** → 底部切出 SpriteFrames 编辑面板

### 4.2 建 3 个动画

这次有 **3 套敌人外观**，每个动画 2 帧：

| 动画名 | 拖入的帧（按顺序） |
|---|---|
| **`fly`** | `art/enemyFlyingAlt_1.png`、`art/enemyFlyingAlt_2.png` |
| **`swim`** | `art/enemySwimming_1.png`、`art/enemySwimming_2.png` |
| **`walk`** | `art/enemyWalking_1.png`、`art/enemyWalking_2.png` |

**操作**（和 [02 章 §3.4](./02-玩家场景.md#34-做第一个动画) 一样）：

1. 把默认的 `default` 动画改名成 **`fly`**，拖入 2 帧
2. 点 **「添加动画」** → 命名 **`swim`**，拖入 2 帧
3. 再点 **「添加动画」** → 命名 **`walk`**，拖入 2 帧
4. **三个动画都勾上「循环」**

**动画速度**：

| 动画 | 速度 | 出处 |
|---|---|---|
| `fly` | **`3`** | 官方正文和成品一致 |
| `swim` | **`4`** | 官方成品 |
| `walk` | **`4`** | 官方成品 |

> 官方正文说"三个都设成 3"，成品是 `fly=3, swim=4, walk=4`。**差别极小，随便**——但要知道有这回事。

### 4.3 缩小

选中 `AnimatedSprite2D` → 检查器 → **`Node2D → 变换 → 缩放`** → 设成 **`(0.75, 0.75)`**

（玩家是 `0.5`，敌人是 `0.75`——敌人看起来比玩家大一圈。）

### 4.4 ✅ 检查点

- SpriteFrames 里有 **3 个动画**：`fly`、`swim`、`walk`
- 每个 **2 帧**，都勾了**循环**
- `AnimatedSprite2D.Scale = (0.75, 0.75)`
- 点每个动画的▶播放按钮都能看到小怪在动

## 5. 碰撞形状（**注意要旋转 90°**）

1. 选中 **`CollisionShape2D`**
2. 检查器 → **`形状`** → `[empty]` → **「新建 CapsuleShape2D」**
3. 检查器 → **`Node2D → 变换 → 旋转 (Rotation)`** → 设成 **`90`**

官方原话（翻译）：*"和 `Player` 场景一样，加一个 `CapsuleShape2D` 做碰撞。**为了把形状和图片对齐，你需要把 `Rotation` 属性设成 90。**"*

**为什么**：胶囊默认是**竖直**的，而敌人的图是**横躺**的——转 90° 才对得上。

**官方成品的数值**（可以直接抄）：

| 属性 | 值 |
|---|---|
| `CapsuleShape2D` 半径 | `37` |
| `CapsuleShape2D` 高度 | `100` |
| `CollisionShape2D` 旋转 | `1.5708` 弧度（= **90°**） |

> **注意**：检查器里「变换 → 旋转」显示的是**度**（`90`），但存进 `.tscn` 文件是**弧度**（`1.5708`）。两个都是同一个角度。

### 5.1 ✅ 检查点

2D 视图里，**横躺的胶囊**覆盖住敌人图片，大小合适。

## 6. 把 `Mob` 加进分组 `mobs`（**别忘**）

这一步是给 [05 章](./05-主场景.md)"一键清空所有敌人"做准备的。

1. 选中 **`Mob`** 根节点
2. 右侧面板 → **「节点 (Node)」** 标签页 → 里面有「**信号**」和「**分组 (Groups)**」两个子标签
3. 切到 **「分组」**
4. 输入框里打 **`mobs`** → 点 **「添加」**

### 6.1 ✅ 检查点

保存后打开 `mob.tscn` 文件，能看到：

```
[node name="Mob" type="RigidBody2D" groups=["mobs"]]
```

> **分组是干什么的**：可以理解为 Godot 版的 **Tag**，但**一个节点可以有任意多个分组**，而且支持**批量广播操作**。
> [05 章](./05-主场景.md) 会用到这一行：
> ```gdscript
> get_tree().call_group(&"mobs", &"queue_free")   # 把场上所有敌人一次性清空
> ```
> **对照 Unity**：Unity 里你要维护一个 `List<Enemy>`，或者 `FindObjectsOfType<Enemy>()`（全场景扫描，慢）。

## 7. 挂脚本 + 写代码

1. 选中 `Mob` → 「附加脚本」（[03 章 §1](./03-玩家脚本.md#1-给-player-挂脚本) 同样的操作）
2. 文件名：**`mob.gd`**（C# 路线：记得在语言下拉里选 **C#**，文件名 `Mob.cs`）
3. 把内容整体替换成：

### 7.1 GDScript —— `mob.gd`

```gdscript
extends RigidBody2D

func _ready():
	var mob_types = Array($AnimatedSprite2D.sprite_frames.get_animation_names())
	$AnimatedSprite2D.animation = mob_types.pick_random()
	$AnimatedSprite2D.play()

func _on_VisibilityNotifier2D_screen_exited():
	queue_free()
```

### 7.2 C# —— `Mob.cs`

```csharp
using Godot;

public partial class Mob : RigidBody2D
{
    public override void _Ready()
    {
        var animatedSprite = GetNode<AnimatedSprite2D>("AnimatedSprite2D");
        string[] mobTypes = animatedSprite.SpriteFrames.GetAnimationNames();
        animatedSprite.Play(mobTypes[GD.Randi() % mobTypes.Length]);
    }

    public void OnVisibleOnScreenNotifier2DScreenExited()
    {
        QueueFree();
    }
}
```

> 🔴 **C# 路线：点「Build」**（新增代码后必需）。

### 7.3 ⚠️ 方法名的不一致（**知道就行，不影响运行**）

| | 官方成品用的名字 |
|---|---|
| GDScript | **`_on_VisibilityNotifier2D_screen_exited`** |
| C# | `OnVisibleOnScreenNotifier2DScreenExited` |

**为什么 GDScript 那个名字看起来"过时"**：这个节点**早期叫 `VisibilityNotifier2D`**，后来改名成 `VisibleOnScreenNotifier2D`，但**成品场景里存的信号连接方法名没有跟着改**（改了连接就断了）。

**实际影响：零**——名字是连信号时自动生成的，**叫什么都能跑，只要方法真的存在**。
你自己做的时候，用编辑器连信号会生成**新的名字**（`_on_visible_on_screen_notifier_2d_screen_exited`）——**那也是对的**，只要代码里的函数名和连接一致即可。

> **建议**：直接用编辑器自动生成的名字（更清晰），本章下面 §8 的连接步骤会说明。

---

## 8. 连 `screen_exited` 信号

1. 选中 **`Mob`** 节点
2. 右侧 → **「节点」** 面板 → **「信号」** 标签
3. 找到 **`screen_exited()`**（属于 `VisibleOnScreenNotifier2D`）
   - **注意**：这个信号是**子节点** `VisibleOnScreenNotifier2D` 的。在「节点」面板里，你会看到当前选中节点**自己的**信号；子节点的信号要先选中子节点再看。
   - **做法**：选中 **`VisibleOnScreenNotifier2D`** 子节点 → 「节点」面板 → 找 `screen_exited` → 双击
4. 弹「连接信号」对话框：

| 字段 | 填什么 |
|---|---|
| **连接到节点** | 改成 **`Mob`**（默认可能是 `VisibleOnScreenNotifier2D` 自己——**要改成 `Mob`**，因为处理逻辑写在 Mob 的脚本里） |
| **接收方法** | GDScript：**`_on_visible_on_screen_notifier_2d_screen_exited`**（自动生成）<br>C#：**`OnVisibleOnScreenNotifier2DScreenExited`**（**手打，大小写一致**） |

5. 点 **「连接」**

> ⚠️ **如果 Godot 自动生成的名字和你代码里的不一样**：两个办法——
> ① 把代码里的函数名改成 Godot 生成的那个；
> ② 在对话框里手动把「接收方法」改成你代码里的名字。
> **总之两边必须一致。**

### 8.1 ✅ 检查点

- `mob.tscn` 文件里出现：
  ```
  [connection signal="screen_exited" from="VisibleOnScreenNotifier2D" to="." method="_on_..."]
  ```
  注意 `from="VisibleOnScreenNotifier2D"`、`to="."`（`.` 表示根节点 `Mob`）——**这就是"子节点发信号、根节点处理"**。

## 9. 运行验证

按 **`F6`** 运行 `mob.tscn`。

### 9.1 现在应该看到什么

| 现象 | 正常吗 | 说明 |
|---|---|---|
| 一个小怪**飘在原地**、动画循环播放 | ✅ **正常** | 敌人的**速度是 [05 章](./05-主场景.md) 的 `Main` 设置的**，这里没有 |
| 小怪种类每次运行不一样 | ✅ | `pick_random()` 生效了 |
| 小怪往下掉 | ❌ | `Gravity Scale` 没设成 0 |
| 什么也看不到 | ❌ | `AnimatedSprite2D` 的 SpriteFrames 是空的，或 `Scale` 设太小 |

> **这是本节的关键认知**：`mob.tscn` 自己**不含移动逻辑**。它只负责"我长什么样、我怎么消失"；"我从哪来、我飞多快"是**生成者（[05 章](./05-主场景.md) 的 `Main`）**的事。
>
> | 谁 | 负责什么 |
> |---|---|
> | `Mob` 场景 | 外观（随机动画）、生命周期（离屏自毁） |
> | `Main` 场景 | 生成位置、方向、速度 |

## 10. 逐段讲解

### 10.1 随机挑一个动画

```gdscript
	var mob_types = Array($AnimatedSprite2D.sprite_frames.get_animation_names())
	$AnimatedSprite2D.animation = mob_types.pick_random()
```

| 步骤 | 干什么 |
|---|---|
| `sprite_frames.get_animation_names()` | 从 `SpriteFrames` 资源里**拿到所有动画名** → `["fly", "swim", "walk"]` |
| `Array(...)` | 包成 GDScript 的 `Array`（这样才能用 `pick_random()` 等便捷方法） |
| `.pick_random()` | **随机挑一个** |

**C# 没有 `pick_random()` 的等价调用**，官方手算下标：

```csharp
        string[] mobTypes = animatedSprite.SpriteFrames.GetAnimationNames();
        animatedSprite.Play(mobTypes[GD.Randi() % mobTypes.Length]);
```

官方解释（翻译）：

> C# 里我们选一个 `0` 到 `2` 之间的随机数来从列表里挑名字（数组下标从 0 开始）。表达式 **`GD.Randi() % n`** 会选中 `0` 到 `n-1` 之间的一个随机整数。

> 💡 **这是个很好的"照搬"教学点**：同一个需求，**GDScript 一行，C# 要手算取模**。差异不在引擎能力，而在"哪门语言的集合 API 更顺手"。

### 10.2 离屏自毁

```gdscript
func _on_VisibilityNotifier2D_screen_exited():
	queue_free()
```

官方原话（翻译）：

> `queue_free()` 这个函数本质上会在**这一帧结束时**"释放"（删除）节点。

| 概念 | 说明 |
|---|---|
| 为什么要删 | 不删的话，飞出去的敌人会**无限累积**——内存和物理计算都被拖垮，游戏越来越卡 |
| `queue_free()` vs `free()` | `queue_free()` 是**帧末延迟释放**（安全）；`free()` 是立刻（危险，除非确定没别的引用） |
| Unity 对应 | `Destroy(gameObject)` —— **同样是延迟到帧末** |

## 11. 和 Unity 的对照小结

| 概念 | Unity | Godot |
|---|---|---|
| 物理实体 | `Rigidbody2D` + `Collider2D` 组件 | **`RigidBody2D` 根节点 + `CollisionShape2D` 子节点** |
| 关掉重力 | `gravityScale = 0` | `gravity_scale = 0` |
| 不互相碰撞 | Layer Collision Matrix（全局） | **`collision_mask = 0`（单个节点，可非对称）** |
| 离屏检测 | `OnBecameInvisible()`（魔法方法） | **`VisibleOnScreenNotifier2D` 节点 + `screen_exited` 信号** |
| 销毁 | `Destroy(gameObject)` | **`queue_free()`** |
| 转碰撞形状 | 转 `Transform` | `CollisionShape2D.rotation`（检查器里是度，文件里是弧度） |
| 随机挑一项 | `Random.Range` 取下标 | GDScript `.pick_random()`；C# `GD.Randi() % n` |
| "多标签" | Tag（只能 1 个） | **分组（可以多个 + 批量广播）** |

## 12. 本章的坑

| 现象 | 原因 |
|---|---|
| 敌人往下掉 | `Gravity Scale` 没设成 `0` |
| 敌人挤成一团、互相弹开 | `Collision → Mask` 里第 `1` 项**没取消勾选** |
| 敌人飞出去后越来越多、越来越卡 | `screen_exited` 信号**没连**，或方法名不一致 |
| 碰撞形状和图不对齐 | `CollisionShape2D.Rotation` 没设成 `90` |
| 所有敌人都长一样 | 忘了 `animation = mob_types.pick_random()`，或 SpriteFrames 里只有一个动画 |
| 敌人太大/太小 | `Scale` 没设 `(0.75, 0.75)` |
| 敌人一动不动 | ✅ **正常**！速度是 [05 章](./05-主场景.md) 设的 |
| C# 报 `GetAnimationNames` 找不到 | 忘了「Build」，或写成了 `get_animation_names()`（C# 里是 `PascalCase`） |
| 报 `Node not found: AnimatedSprite2D` | 子节点名字和 `GetNode<T>("...")` 里的字符串不一致 |
| 后面"重开游戏"旧敌人还在 | `Mob` **没加进 `mobs` 分组**（[§6](#6-把-mob-加进分组-mobs别忘)） |
