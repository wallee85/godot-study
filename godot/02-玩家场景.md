# 02 · 玩家场景（搭出 `player.tscn`）

> 官方对应节：[Creating the player scene](https://docs.godotengine.org/en/stable/getting_started/first_2d_game/02.player_scene.html)
> **本章不写脚本**，只搭节点树。做完你会有一个"有图、有判定框"的玩家——[03 章](./03-玩家脚本.md) 才让它动起来。

---

## 0. 本章导航

| | |
|---|---|
| **开始时** | 空项目 + 素材已导入（[01 章](./01-项目设置.md) 完成） |
| **结束时** | `player.tscn`：有动画、有碰撞判定框、能被单独运行（还不会动） |
| **耗时** | 20~30 分钟 |
| **产出** | `player.tscn` |

**最终结构**（做完对照一下）：

```
Player (Area2D)                 ← 根节点
├─ AnimatedSprite2D             ← 负责画（2 个动画，各 2 帧）
├─ CollisionShape2D             ← 负责"判定框"（胶囊形）
└─ Trail (GPUParticles2D)       ← 可选：移动拖尾
```

## 1. 新建场景，选根节点

### 1.1 先想清楚"根节点该用什么"

官方原话（翻译）：

> 一个场景的**根节点应该反映这个对象的**"**是什么**"。
> ……
> Godot 也提供了 `CharacterBody2D`，专门为 2D 角色设计……**在很多真实项目里，`CharacterBody2D` 会是玩家和敌人的更好选择。但本教程聚焦于能适用于更广泛节点的核心概念。**

| 我们的对象 | 选什么 | 为什么 |
|---|---|---|
| **`Player`** | **`Area2D`** | 我们只需要"**检测有没有东西撞到我**"，不需要物理推动（位置完全由按键决定） |
| `Mob`（[04 章](./04-敌人.md)） | `RigidBody2D` | 敌人需要"被赋予速度后自己飞"的**真物理** |

> **对照 Unity**：`Area2D` ≈ `Collider2D` 勾上 **`Is Trigger`**（不阻挡、只通知）。
> **但有个重要差异**：Unity 的触发器要求"**双方至少一个带 `Rigidbody2D`**"（新手最常踩的坑）；**Godot 的 `Area2D` 检测 `RigidBody2D` 不需要额外配合**，它自己就会发 `body_entered` 信号。

### 1.2 操作

1. 菜单 **`场景 → 新建场景`**（Scene → New Scene）
2. 左上角「场景」面板里，点 **「+」按钮**（或按 `Ctrl+A`）打开"创建新节点"对话框
3. 搜索框里输入 **`Area2D`** → 选中 **`Area2D`** → 点「创建」
4. 现在根节点叫 `Area2D`——**双击它的名字**，改成 **`Player`**
5. 保存：菜单 **`场景 → 保存`**（或 `Ctrl+S`）→ 文件名填 **`player.tscn`** → 保存位置是**项目根目录**（默认就是）

### 1.3 ✅ 检查点

- 「场景」面板里只有一个节点 `Player`
- `Player` 旁边有一个 **⚠️ 黄色警告图标**
- 鼠标悬停在警告上，提示类似 *"`Area2D` 需要有形状才能检测碰撞或重叠"*

> **这个警告先不管它**。官方说（翻译）：*"我们可以**暂时忽略这个警告**，因为我们要先设置玩家的视觉（用动画精灵）。等视觉做好了，我们再添加碰撞形状作为子节点。**这样可以基于精灵的实际外观来准确调整形状的大小和位置。**"*

## 2. 锁定子节点（官方提醒的省命操作）

在加子节点**之前**先做这一步，否则你后面会无数次手滑点中小小的碰撞形状把它拖歪。

1. 选中 `Player` 节点
2. 在「场景」面板**顶部工具栏**上，找到一个**锁形图标右边的按钮**（图标看起来像"方块里套方块"）
3. 悬停提示是（翻译）：*"**把选中节点和它的子节点编组**。这样在 2D/3D 视图里点击任意子节点时，都会选中父节点。"* —— **点亮它**

> ⚠️ **别看错按钮**：工具栏**最左边那个锁形图标**是「**锁定所选节点**（`Ctrl+L`）」，提示文字是"**锁定选定的节点，防止选择和移动**"——那是**相反**的功能，点亮它只会让你之后在视口里**选不中、拖不动**这个节点。
> **选错锁上了**？再点一次（或 `Ctrl+L`）取消。节点处于锁定状态时，场景树里它的名字右边会多一个**小锁图标**，看这个图标就能确认。

**快捷键：`Ctrl+G`**

> **效果**：以后你在 2D 视图里点任何位置，选中的都是 `Player` 整体，**不会误触子节点**。

## 3. 加动画精灵 `AnimatedSprite2D`

### 3.1 添加节点

1. 确保选中 `Player`
2. 按 **`Ctrl+A`** → 搜索 **`AnimatedSprite2D`** → 创建

### 3.2 创建 `SpriteFrames` 资源

刚加上去时，`AnimatedSprite2D` 旁边也有 ⚠️ —— 因为它还没有"帧数据"。

1. 选中 `AnimatedSprite2D`
2. 看右侧**检查器**，找到 **`动画 (Animation) → 精灵帧 (Sprite Frames)`** 属性
3. 点那个 `[empty]` 下拉 → 选 **「新建 SpriteFrames」**（New SpriteFrames）

### 3.3 打开 SpriteFrames 编辑面板

1. **点一下刚刚创建出来的那个 `SpriteFrames`**（属性栏里现在显示的是资源名）
2. **编辑器底部**会切出一个 **「SpriteFrames」** 面板

**这个面板长这样**：

```
┌──────────────────────────────────────────────────────┐
│ [+ 添加动画] [重命名] [删除]        [从精灵表添加帧] │  ← 顶部按钮
├──────────────┬───────────────────────────────────────┤
│ 动画列表     │  当前动画的帧（图片缩略图网格）        │
│  ▸ default   │  [帧1] [帧2]                          │
│              │                                       │
│  循环 ☑  速度 5.0     ← 下面有"循环"勾选框和速度      │
└──────────────┴───────────────────────────────────────┘
```

### 3.4 做第一个动画

| 步骤 | 操作 |
|---|---|
| 1 | 左侧列表里有一个默认的 **`default`** 动画 → 双击它改名（或选中后用「重命名」）→ 改成 **`right`** |
| 2 | 右侧是"帧"区域 → 从**左下角文件系统面板**里，把 `art/playerGrey_walk1.png` **拖进去** |
| 3 | 再把 `art/playerGrey_walk2.png` **拖进去**（顺序：walk1 在前，walk2 在后） |
| 4 | 底部确认 **「循环」是勾上的**（左右走要循环播放） |
| 5 | 「速度」设成 **`5`**（每秒 5 帧） |

> **⚠️ 关于动画名——这里有个"官方教程 vs 官方成品"的不一致**：
>
> | 你跟着谁做 | 动画应该叫什么 |
> |---|---|
> | **官方教程正文** | `walk` |
> | **官方成品代码/场景** | **`right`** |
>
> **本篇统一用 `right`**（和官方成品一致，后面所有代码都按 `right` 写）。
> 如果你跟着官方教程正文起了 `walk`，**那 [03 章](./03-玩家脚本.md) 的代码里也要全部改成 `walk`**——**两边必须同名，大小写敏感**。名字对不上**不会报错，只是"角色不动"**。

### 3.5 做第二个动画

| 步骤 | 操作 |
|---|---|
| 1 | 点面板顶部的 **「添加动画」**（Add Animation）→ 命名为 **`up`** |
| 2 | 拖入 `art/playerGrey_up1.png` 和 `art/playerGrey_up2.png` |
| 3 | 循环 **勾上**，速度 **`5`** |

### 3.6 ✅ 检查点

- SpriteFrames 面板的动画列表里有 **2 个动画**：`right`、`up`
- 每个动画里有 **2 帧**
- 选中 `right` 动画时，点面板上的▶播放按钮，能看到小人在原地跑
- 两个动画的「循环」都是**勾上**的

## 4. 缩小精灵

官方原话（翻译）：*"玩家图片对游戏窗口来说有点太大了，我们需要把它们缩小。"*

1. 选中 **`AnimatedSprite2D`** 节点（不是 `Player`）
2. 检查器里找到 **`Node2D → 变换 (Transform) → 缩放 (Scale)`**
3. 把 `Scale` 设成 **`(0.5, 0.5)`**

> **对照 Unity**：Unity 里你会调 `Pixels Per Unit`（让引擎重新解释这张图有多大）。
> **Godot 没有 PPU**——就是**直接缩放节点**（[01 章 §5](./01-项目设置.md#5-要不要改像素过滤官方素材不用改)）。
> 官方成品里：玩家 `Scale = (0.5, 0.5)`、敌人（[04 章](./04-敌人.md)）`Scale = (0.75, 0.75)`。

## 5. 加碰撞判定框 `CollisionShape2D`

### 5.1 添加节点和形状

1. 选中 `Player`
2. `Ctrl+A` → 搜索 **`CollisionShape2D`** → 创建
3. 选中它 → 检查器里的 **`形状 (Shape)`** → 点 `[empty]` → **「新建 CapsuleShape2D」**

官方为什么用胶囊（翻译）：

> 对这个角色来说，**`CapsuleShape2D` 是最贴合的**。

### 5.2 调整大小（关键：让它贴合精灵）

现在 2D 视图里会出现一个**胶囊形的轮廓**（半透明填充 + 两个圆形手柄）。

**两种调整方式，任选**：

| 方式 | 操作 |
|---|---|
| **拖手柄**（推荐） | 鼠标拖胶囊上下两端的**圆形手柄**改高度，拖**中点的手柄**改半径 |
| **填数值**（精准） | 选中 `CapsuleShape2D` 资源 → 检查器里改 `半径 (Radius)` 和 `高度 (Height)` |

**官方成品的数值**（可以直接抄，省得调）：

| 属性 | 值 |
|---|---|
| `半径 (Radius)` | **`27`** |
| `高度 (Height)` | **`68`** |

**目标**：胶囊大致**刚好包住精灵**——上下留一点余量，不要漏出身体，也不要大出一圈（判定框太大 = 容易"莫名其妙被撞死"）。

### 5.3 ✅ 检查点

1. 2D 视图里，胶囊**覆盖住小人**，大小合适
2. 🔴 **`Player` 节点旁边的黄色警告消失了** —— 这是"形状已就位"的标志

> **注意**：`CollisionShape2D` 节点本身在 2D 视图里会显示一个**红色小图标**（那是节点的标记，不是判定框）。真正的判定框是那个**半透明填充的胶囊轮廓**。

## 6. （可选但推荐）拖尾粒子 `Trail`

官方成品比教程正文多了一个 `Trail` 节点，让玩家移动时有拖尾。**不做也能完成游戏**，但做了更好看。

1. 选中 `Player` → `Ctrl+A` → 搜索 **`GPUParticles2D`** → 创建
2. 改名成 **`Trail`**
3. 检查器里设：

| 属性 | 值 | 作用 |
|---|---|---|
| `z_index` | **`-1`** | 画在玩家**下面**（不然拖尾会盖住角色） |
| `数量 (Amount)` | **`10`** | 同时存在 10 个粒子 |
| `纹理 (Texture)` | `art/playerGrey_walk1.png` | 用玩家图当粒子形状 |
| `速度缩放 (Speed Scale)` | **`2.0`** | 粒子跑得快一点 |
| **`过程材质 (Process Material)`** | 点 `[empty]` → **新建 ParticleProcessMaterial** | 粒子的行为参数 |

4. 展开新建好的 `ParticleProcessMaterial`（「过程材质」），设：

| 属性 | 值 | 作用 |
|---|---|---|
| `重力 (Gravity)` | **`(0, 0, 0)`** | 粒子不往下掉 |
| `缩放 (Scale) → 缩放曲线 (Scale Curve)` | 新建 **`CurveTexture`**，曲线**起点 `0.5`**、**终点 `0.324`** | 🔴 **让粒子和玩家同尺寸**——见下面的坑 |
| `颜色 (Color) → 颜色 (Color Ramp)` | （可选）新建 **`GradientTexture1D`**：颜色保持白色，**起点 alpha `0.5`**、**终点 alpha `0`** | 粒子边飞边淡出，更像"残影" |

> 🔴 **最容易踩的坑：拖尾是一大块色斑，比玩家大一圈**
> `AnimatedSprite2D` 设了 `Scale = (0.5, 0.5)`，但 `Trail` **没有跟着缩放**——它的贴图和精灵一样大，却按 **`1.0`（原始像素尺寸）** 画出来，于是粒子看起来是玩家的**两倍**。
> 官方成品的解法就是上面那条 **`缩放曲线`：起点 `0.5`（和精灵对齐）→ 终点 `0.324`**（快消失时缩小），再配合 `颜色 Color Ramp` 淡出。
> **不想建曲线？** 最低限度的替代方案：直接给 **`Trail` 节点本身**设 `缩放 (Scale) = (0.5, 0.5)`。差别只是粒子不会"边飞边变小"。
> ⚠️ **两种方案只能选一种**。同时用会变成 `0.25` 倍，小得看不见。

> ⚠️ **如果你不做 `Trail` 节点**，[03 章](./03-玩家脚本.md) 的代码里有一行 `$Trail.rotation = 0`，**必须删掉**，否则运行时报 `Node not found: Trail`。代码处会有提示。

## 7. 加 `z_index`（让玩家永远画在敌人上面）

1. 选中 **`Player`** 根节点
2. 检查器 → **`CanvasItem → 绘制顺序 (Ordering) → z_index`**
3. 设成 **`10`**

> **为什么**：敌人的 `z_index` 是 0。`z_index` 大的画在上面。不设的话，敌人飞过来时可能**盖住玩家**，看起来像"判定出错了"。
> **对照 Unity**：Unity 里你要去 Project Settings 里预先定义 Sorting Layer，再给每个 SpriteRenderer 设 Order in Layer。**Godot 只要一个 `z_index` 数字**（[00 章 §6.2](./00-核心概念地图.md#62-官方成品里的-z-顺序技巧)）。

## 8. 保存 + 单独运行测试

### 8.1 保存

**`Ctrl+S`**（如果标题栏有 `*` 号说明还没保存）。

### 8.2 单独运行这个场景

按 **`F6`**（运行**当前场景**）。

**你现在应该看到**：

| 现象 | 正常吗 | 说明 |
|---|---|---|
| 屏幕是灰的，只在**左上角**（或**下方中央**）看到小人 | ✅ **正常** | 它就停在 `player.tscn` 里保存的位置上：官方成品是 `(0,0)`=左上角，**本项目改成了 `(240, 450)`**（= [05 章](./05-主场景.md) 的起点）→ 出现在下方中央。等 [03 章](./03-玩家脚本.md) 的脚本接管后，它会因为 `_ready()` 里的 `hide()` 而**彻底消失** |
| **什么都没有**（连半个都没有） | ✅ 如果你已经写了 03 章的脚本 | `_ready()` 里的 `hide()` / `Hide();` 正在起作用 → 见 [03 章 §6](./03-玩家脚本.md#6-运行验证这次真的能动了) 第一步 |
| 弹出一个游戏窗口 | ✅ | 那是运行窗口，关掉它 |
| 报错 `Node not found` | ❌ | 检查子节点名字拼写 |
| 报错说脚本为空 | ✅ 正常 | 还没挂脚本 |

> **`F6` 是 Godot 的独门好处**：官方开头就说了（翻译）：*"做一个独立 `Player` 场景的一个好处是：**我们可以在其他部分还没做出来之前，就单独测试它。**"*
> **对照 Unity**：要单独测一个 Prefab，得建测试场景、拖 Prefab 进去、设为启动场景、测完改回来。Godot 里就是 `F6`。

## 9. 完整结构对照（做完检查一下）

| 节点 | 类型 | 关键属性 | 备注 |
|---|---|---|---|
| **`Player`** | `Area2D` | `z_index = 10`，`Position = (240, 450)`（[§9 说明](#9-完整结构对照做完检查一下)），**已编组子节点** | 根节点 |
| `└ AnimatedSprite2D` | `AnimatedSprite2D` | `Scale = (0.5, 0.5)`，SpriteFrames 有 `right`/`up` 两个动画 | |
| `└ CollisionShape2D` | `CollisionShape2D` | `CapsuleShape2D`（半径 27 / 高 68） | 那个 ⚠️ 消失才算对 |
| `└ Trail` | `GPUParticles2D` | `z_index = -1`、`Amount = 10`、过程材质 `Scale Curve = 0.5 → 0.324` | **可选**；不设 `Scale Curve` 会比玩家大一倍 |

**`player.tscn` 存下来大概是这样**（可以打开文件对照，Godot 的场景文件是**纯文本**）：

```
[gd_scene format=3 uid="uid://..."]
[node name="Player" type="Area2D"]
z_index = 10
position = Vector2(240, 450)
[node name="AnimatedSprite2D" type="AnimatedSprite2D" parent="."]
scale = Vector2(0.5, 0.5)
...
```

> **为什么这里有个 `position = Vector2(240, 450)`**：官方成品的 `player.tscn` 里 `Player` 根节点**没有 `position`**（= `(0,0)`），所以 `F6` 单独跑时小人出现在**左上角**（只露出半个）。本项目把它设成 **`(240, 450)`** —— 也就是 [05 章](./05-主场景.md) 里 `StartPosition` 的坐标（水平正中、偏下），这样 **`F6` 测试看到的起点就和正式游戏一致**。
> **对正式游戏零影响**：运行时 `Main` 会调 `$Player.start($StartPosition.position)`，[03 章](./03-玩家脚本.md) 的 `Start()` 里那句 `Position = position;` 会**覆盖**场景里存的位置。

> **`.tscn` 是纯文本**是 Godot 的一大优势：**git diff 能看懂**、冲突能手工解决、出问题能直接读文件确认编辑器存了什么。

## 10. 本章的坑

| 现象 | 原因 |
|---|---|
| `Player` 旁边的 ⚠️ 不消失 | 没加 `CollisionShape2D`，或者加了但 `Shape` 还是 `[empty]` |
| 精灵太大/太小 | `AnimatedSprite2D.Scale` 没设成 `(0.5, 0.5)` |
| 拖尾是一大块、比玩家大一圈 | `Trail` 没跟着 `AnimatedSprite2D` 的 0.5 缩放（贴图按 `1.0` 原始尺寸画）→ 在 `ParticleProcessMaterial → 缩放曲线 (Scale Curve)` 把起点设成 `0.5`；**或**直接给 `Trail` 节点设 `Scale = (0.5, 0.5)`（二选一） |
| 后面运行时角色不动 | **动画名不一致**（`right` vs `walk` vs `Right`）。**脚本里写什么名，SpriteFrames 里就得叫什么名** |
| 2D 视图里老是拖歪子节点 | 没做「编组」（`Ctrl+G`，[§2](#2-锁定子节点官方提醒的省命操作)） |
| 视口里**点不中/拖不动**任何节点 | 误点了工具栏最左边的**锁定**按钮（`Ctrl+L`）。再按一次 `Ctrl+L` 解锁；**编组是它右边**那个按钮（`Ctrl+G`） |
| 保存时弹出"另存为" | 第一次保存要输文件名 `player.tscn`，注意存在**项目根目录** |
| SpriteFrames 面板里找不到"从精灵表添加帧" | 你打开的是检查器里的资源，不是底部面板。先**点一下 `SpriteFrames` 资源**才会切出底部面板 |
| `F6` 报 `Invalid call. Nonexistent function 'x'` | 脚本里有语法错误，或挂到了错的节点上 |
